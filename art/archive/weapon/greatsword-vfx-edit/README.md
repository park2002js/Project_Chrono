# 대검 검기 수정 작업실

**1타는 연보라,2타는 연하늘 단색이며3타도 같은 방향에 같은 색을 사용합니다.**

- [1타 — 연보라 #E5D2FF](aseprite/greatsword-swing.aseprite)
- [2타 — 연하늘 #C3EAFF](aseprite/greatsword-swing-attack2.aseprite)
- [3타 — 원래1·2타 호 합성](aseprite/greatsword-swing-attack3.aseprite)
- [1·2·3타 전체 비교](attack-combo-preview.png)·[1·2타 비교](attack2-palette-preview.png)
- [3타4장 비교](attack3-combined-preview.png)·[순서 재생 GIF](attack3-x-preview.gif)

1·2타는 `VFX_EDIT`,3타는 `SLASH_A_EDIT`·`SLASH_B_EDIT` 레이어에서 수정합니다.1·2타 편집 파일/출력은 반전 전 방향이며 실제2타에서는 좌우 반전합니다. 비교판에는2타를 반전해 보여줍니다.

1. 타임라인의1~4번 프레임에서 원하는 모양·색을 수정합니다.
2. 같은 파일에 저장합니다.
3. 전용 출력 도구를 더블클릭합니다: [1타](Export-PNG.cmd)→`png/`, [2타](Export-PNG-Attack2.cmd)→`png-attack2/`, [3타](Export-PNG-Attack3.cmd)→`png-attack3/`. 개별4장과 시트가 갱신됩니다.

3타 모션과 노출은 [현행 R14 검토판](../player-combo-preview-r13/README.md)을 따릅니다. 사용자 번호 오독 정정과 새 주문으로 **1타1~24+2타16~45의54장**을 직접 연결했습니다. 23·24번째는보라1단계만,25번째부터두검기를표시합니다. 보라만26번째2단계선행,35번째까지함께잔광을유지하고36번째동시에사라집니다. 좌우 가림은 겹친 부분에만 적용하며 비겹침 원본은 모두 보존합니다. 이전R03~R13의 모션/이동 배치는 제작 이력이며 실제 Unity 연결과 새 판의 최종 미술 승인은 후속입니다.

## 현행 색과 형태

| 대상 | 색 | 형태 |
| --- | --- | --- |
| 1타 /3타 A | 연보라 `#E5D2FF` 단색 | 원본 방향의 호 |
| 2타 /3타 B | 연하늘 `#C3EAFF` 단색 | 반전 방향의 호 |

1·2타는 전체 불투명RGB만 바꿨습니다.4장 형태·알파·셀 위치·피벗과 숨김 원본 비교/가이드는 유지합니다. 이전 흰색1타와 흰색+금빛 주황 외곽2타는 이번 사용자 지시로 대체됐습니다.

3타는 **현재1타 보라 호 + 실제2타 방향으로 반전한 하늘 호를 같은 피벗에 그대로 합성**했습니다. 기울임·압축·안쪽 끝 변형은 추가하지 않습니다. 중앙x35 기준 **왼쪽 겹침은 하늘이 앞,오른쪽 겹침은 보라가 앞**입니다. 두 원본 그림 전체를 유지한 채 겹친 부분만 앞그림에 가리고,겹치지 않은 부분은 모두 표시합니다. 원본을 좌우 반으로 자르지 않습니다.

현행 R14의 색별 노출은 JSON/CSV를 기준으로 합니다.

- F1–22: 검기 없음
- F23–24: 보라1단계만 / F25: 두 색의 큰 호 / F26: 보라2단계·파랑1단계
- F27–29: 두 색2단계, F30–32: 두 색3단계, F33–35: 두 색 마지막 잔광
- F36–54: 검기 없음

`SLASH_A_EDIT`는1타 원본 보라 호,`SLASH_B_EDIT`는반전한2타 하늘 호입니다. 하늘 레이어 위에`CROSSOVER_PURPLE_RIGHT` 덮개로 오른쪽 보라를 앞으로 둡니다. 색/모양 변경 시 덮개도 함께 맞춥니다. 이4장native는 같은 단계의 원본 보관용이며26번째처럼 색별 단계가 다른 합성은 R14 JSON/CSV를 따릅니다. 큰피해1회 방침을 유지하며 실제 게임 연결은 후속입니다.

## 레이어와 유지할 기준

- `VFX_EDIT`:1·2타에서 실제 수정할 이미지
- `REFERENCE_ORIGINAL`: 숨김/잠금 상태의 원본 비교용. 비교 후 다시 숨김
- `GUIDE_PIVOT`: 숨김/잠금 상태의 중심 십자
- 공통 캔버스70×66px, 중심(35,33)px,16PPU. 프레임마다 캔버스나 위치를 바꾸지 않음
- `PIVOT_KEEP_35_33` Slice에 중심점 저장
- 이미지1~4는 큰 호→남은 호→작은 조각→잔광 순서

출력 도구는 원본 비교/가이드를 자동 제외하고 새 그림 레이어는 저장 당시 보이는 상태로 포함합니다. Aseprite 저장 없이 출력하면 마지막 저장본을 사용합니다.

## 출력과 검사

각 `png/`·`png-attack2/`·`png-attack3/`에70×66 개별PNG4장,280×66 가로 시트, `frames.json`을 저장합니다. JSON에는 피벗/순서/16PPU/방향별 색/2타 반전/3타 단일피해 방침을 기록합니다. 현행 노출 메타데이터는 R14의54칸 JSON/CSV와 일치하며 이전 배치는 이력입니다. 실제 Unity 연결은 후속입니다.

R14의export.lua·png-attack3/frames.json을 실제54노출칸에 맞췄습니다. Aseprite 임시폴더 출력 종료0·PNG5개 바이트동일·출력JSON54칸 일치를 확인해 메타데이터를 반영했습니다. 원본4장의 이미지와 크기·1·2타는 바꾸지 않았습니다. 이전 출력 검사는 당시 이력입니다.

Aseprite1.3.18.6 재열기/세 전용 출력cmd 실행과PNG/시트 일치·70×66·피벗을 확인했습니다.1·2타는 알파1895→312→30→5픽셀/숨김 원본·가이드/메타데이터 보존과 단색을,3타는 원본 두 호/한번 반전·왼쪽하늘/오른쪽보라 앞뒤·2548→624→60→10픽셀·색별F37/38/40 예외·비겹침 보존·시작/종료·추가 잘림 없음을 검사했습니다. 각 `attack1-validation.json`·`attack2-validation.json`·`attack3-validation.json`을 따릅니다. 최초 흰색 준비 기록 `validation.json`은 제작 당시 이력입니다.

GIF는 순서 확인용이며 반복 전 빈 화면은 휴지 구간으로 VFX의 다섯 번째 그림이 아닙니다. 미리보기 시간은 Unity 최종 시간으로 사용하지 않습니다. 원작 자료와 우리 검/Player 원본은 수정하지 않았고 이번 VFX는 아직 게임에 연결하지 않았습니다.
