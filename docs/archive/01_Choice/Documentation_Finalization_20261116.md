# 선택 주제

주제: project 외부의 자료를 최종 결과 중심으로 정리하고 불필요한 중간 파일을 삭제

- 2026-11-16 최초 요청은 “지금까지 했던 것들 파일들을 모두 정리”, “project쪽을 제외하고 나머지 문서들을 모두 정리”, “중간 확인을 위해 기록했다거나 이런것들도 모두 종합해서 다 결과가 되도록”이었다
- 같은 날 후속 요청에서 의미 없는 지난 파일·최종 확정되지 않은 것·일회성 자료·지난 오류와 로그를 모두 지우도록 명시했다
- 후속 삭제 요청에 따라 최초의 과정 자료·복구 사본 보존 방식은 최종 결과 중심의 실제 삭제로 바뀌었다

# 선택 사안 1

- 선택: Unity 프로젝트는 제외하고 문서·아트 자료를 정리
- 이유: 사용자가 project를 명시적으로 제외
- 적용: 현재 사양은 GAME_SPEC, 결과는 docs/results, 제출 보고서·포스터는 docs/report, 확정 자산과 편집 원본은 art/archive에 유지. 프로젝트 보존 검사는 [정리 결과](../../results/Cleanup_Result.json)를 따름

# 선택 사안 2

- 선택: 중간 판본·미확정/반려 시안·일회성 전송/검사·지난 오류 로그·시험/복구 사본을 실제 삭제
- 이유: 사용자가 앞선 분류 정리 뒤에도 불필요한 파일이 남아 있음을 지적하고 삭제를 직접 요청
- 적용: Temp와 아트 작업 사본, 이전 STATUS/PLANS, 04_Process, 중복 검증 목록·원시 빌드 로그·일회성 보고서 참고 자료를 제거. 의미 있는 결정 이유·분석·문제 해결 결론은 유지
- 구분: 최종 편집에 필요한 프레임·피벗·팔레트·배치 메타데이터, 음원 출처와 생성 원본은 일회성 진단 자료로 취급하지 않음
- 복구 범위: 별도 백업 없이 실제 삭제. Git에 기록된 파일은 Git으로 복원할 수 있고, 추적되지 않은 작업·캐시·Temp에는 별도 복구 사본이 없음

# 선택 사안 3

- 선택: 최종 확인 사실과 이번 정리 결과만 간결하게 기록
- 이유: 원시 로그·중간 파일을 다시 모아 불필요한 보관소를 만드는 것을 피하고 결과를 읽을 수 있게 하기 위한 후속 요청의 적용
- 적용: [Verification_Summary](../../results/Verification_Summary.json)에 Windows 빌드·소스 정리·보고서 확인 범위를 남기고 [Cleanup_Result](../../results/Cleanup_Result.json)에 실제 삭제와 최종 결과 보존 검사를 기록
- 구분: 미완 기능·미실행 성능 비교·전체 실행 파일 시연은 완료로 바꾸지 않음
