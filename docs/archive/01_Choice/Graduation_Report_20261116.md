# 선택 주제
주제 : 최종 졸업작품 보고서의 범위와 양식

현재 결과는 [제출물 안내](../../report/README.md)의21쪽 보고서와 포스터다. 이후 사용자 정리 요청으로 과거 보고서·주석 전 사본·외부 참고 예시·렌더·원시 로그는 삭제했고, 이 문서에는 선택 이유와 최종 확인을 남겼다.
- 2026-11-16 사용자는 `새 폴더/Graduation_Report_Outline_20261116.md`를 기준으로 Unity와 지금까지의 작업을 모아 최종 보고서를 작성하도록 요청했다.

# 선택 사안 1
- 선택 : 준비된 7장 목차를 따르되 Class Diagram과 Sequence Diagram을 생략
- 이유 : 사용자가 부득이한 사정으로 해당 다이어그램이 없다고 설명
- 적용 : 객체의 책임·수명·관계 표와 실제 처리 과정 서술로 구조를 설명

# 선택 사안 2
- 선택 : UX 문제 해결, 최적화 고려, 객체지향과 역할 분리의 판단을 강조하고 UniTask 사용 부분의 실제 코드를 구체적으로 제시
- 이유 : 사용자가 최종 보고서의 강조점으로 직접 지정
- 적용 : AI 활용 절은 디버깅·주석·UniTask 연동 사례를 다루며 프로젝트 전체의 배타적 기여 이력이나 임의의 기여율을 단정하지 않는다. 구현·검증·성능 실측의 범위를 구분한다

# 선택 사안 3
- 선택 : 소프트웨어학과·32211853·박지성의 표지 정보
- 이유 : 작성 중 사용자의 직접 답변
- 적용 : 목차 문서의 DOCX 편집 원본·PDF 제출본 형식과 `docs/report/` 위치를 사용

# 선택 사안 4
- 선택 : 독자는 보고서와 제출 Unity 프로젝트만 확인한다고 가정하고 분량을 축약하며 참고문헌은 공식 문서·GitHub 플러그인만 수록
- 이유 : 사용자가 42쪽 초안이 너무 길고 art·Temp 등 확인할 수 없는 자료에 의존한다고 지적
- 적용 : 7장 목차는 유지하고 내부 기록·검증 파일 인용과 부록을 제거. 구현 위치는 Unity 루트의 Assets·Packages·ProjectSettings로 안내하고 조작 방법·UniTask 핵심 코드 4개는 본문에 통합

# 선택 사안 5
- 선택 : Katana ZERO, Enter the Gungeon, Titan Souls, Sephiria를 기획 레퍼런스로 서론 첫머리에 명시
- 이유 : 사용자가 실제 참고한 네 작품을 직접 제시하고 초반 소개를 요청
- 적용 : 1.1에서 네 작품을 밝히고 2.1에서 기획·기술 검토를 구분. 참고문헌에는 Unity 공식 문서 2개·UniTask GitHub 1개만 유지

# 선택 사안 6
- 선택 : PDF 주석 9개에 따라 버전 확인 경로·일부 실행 안내·빌드 성공 설명·외부 자산 소개 문장을 삭제하고 목차에 하위 절을 표시
- 이유 : 사용자가 지정 문구의 삭제와 비어 보이는 목차의 보완을 직접 요청
- 적용 : 3.1·5.1·5.2·6.3의 지정 문장을 정리하고 목차를 장·절 2단계로 갱신. UniTask 라이선스와 실제 코드 설명은 유지

# 선택 사안 7
- 선택 : 패턴 파악 후 공격을 계획하는 경험을 개발 동기로 설명하고 탐색전의 이득을 차별화 의도로 강조. UX 불편의 원인 규명 어려움과 알파·베타 개발 후 GIGDC 출품 목표를 추가
- 이유 : 사용자가 개발 동기·겪은 어려움·향후 방향을 직접 설명
- 적용 : 1.1·2.1·7.2·7.3에 반영. 시장에 동일 게임이 없다는 보편적 주장 대신 개발자의 경험·설계 의도로 서술하며 알파·베타 및 출품은 향후 목표로 구분

# 선택 사안 8
- 선택 : Hitbox·CollisionBox를 작성한 이유와 물리 판정의 계산·처리 흐름을 상세히 설명
- 이유 : 사용자가 단순 Collider 처리로 충족하기 어려운 상황을 인식하고 두 클래스로 해결했다는 설계 판단을 강조하도록 요청
- 적용 : 4.3에 접촉과 전투 규칙의 차이, 수신자·피해 허용 분리, 회전 사각과 명시적 질의 시점, 공격별 중복·취소, 버퍼 재사용, 탄환 이동 구간 검사의 책임을 보강. 실제 코드 2개와 Unity 공식 BoxCast 문서를 추가. 기존 피드백과 7장 구조를 유지하고 총 18쪽으로 갱신

# 선택 사안 9
- 선택 : Draw & Slash의 두 점 입력 원리와 최소한의 상호작용을 목표로 한 선택 이유를 상세히 설명하고 Input System을 상태별 키 구성·향후 키 설정 계획과 연결
- 이유 : 사용자가 원하는 직선을 간단히 그릴 방법을 찾은 과정이 핵심이라고 설명하고 입력 도구의 선정 이유를 직접 제시
- 적용 : 4.1·4.2에 화면 좌표 변환, 시작점·방향점과 고정 길이, 미리보기·확정·취소, 경로 수명·소비와 연출의 연결을 보강. 실제 코드 1개와 데이터 흐름 표를 추가하고 현재 Action Map 전환과 향후 키 설정 화면·바인딩 저장을 구분

# 선택 사안 10

- 이유 : 사용자가 저장 구현의 도구 선정 근거를 위 개념들의 차이와 함께 설명하도록 요청
- 적용 : 4.4에 C# 문법과 작업 타입, PlayerLoop 대기와 RunOnThreadPool, 복사본·순차 큐의 기록 순서, 현재 오버로드의 메인 흐름 복귀, 코루틴 연결과 성능 미측정 범위를 설명. 6.3의 실제 코드 4개를 유지하고 Microsoft 공식 문서만 참고문헌에 추가
