# 선택 주제
주제 : F-P01 입력 콜백과 전달 판단의 책임을 세피리아 구조에 맞게 분리
- 2026-11-15 사용자는 Input Actions가 PlayerInputController의 함수로 값을 전달하고, 컨트롤러가 해당 값을 Player에 전달할지를 결정하도록 요청했다.
- 입력이 없을 때와 BlockInput 활성화·해제 때의 처리 및 차단을 설정하는 주체를 세피리아 코드에서 분석한 뒤 현재 환경에 적용하도록 명시했다.
- 현재 사양·참고 파일·구현·검사와 시퀀스의 원본은 [GAME_SPEC P02·2.1.1](../../GAME_SPEC.md#211-f-p01-구현확인과-sequence-diagram)이다. 이 기록은 요청·선택 경위를 보존한다.

# 선택 사안 1
- 선택 : 사용자 확정 — Input Actions→PlayerInput UnityEvents→PlayerInputController 입력 콜백·캐시→Update의 전달 판단→Player 흐름을 적용한다.
- 이유 : 사용자가 입력값 수신과 전달 여부 판단을 PlayerInputController의 책임으로 명시했다. 별도의 선택 이유는 미기록이다.
- 제시된 다른 선택 사안들
  - 기존 구현은 컨트롤러가 Keyboard/Mouse를 매 프레임 직접 조회했다. 이번 요청으로 대체하며, 사용자가 별도로 고른 대안은 아니다.

# 선택 사안 2
- 선택 : 사용자 요청에 따른 적용 — 세피리아의 차단 진입 시 이동 초기화, 차단 유지 시 사용자 이동 전달 생략, 조준 분리와 차단 해제 시 키 재조회 없음의 흐름을 현재 구현 범위에 적용한다. 현재 차단 수명은 PlayerSpawner의 최초 연결과 GameManager의 월드 준비·세션 종료가 관리한다.
- 이유 : 사용자가 세피리아의 입력 없음·BlockInput 처리와 활성화 주체까지 분석하여 적용하도록 요청했다. 현재 게임에 없는 네트워크 전파·무기 교체·시전 맵을 도입할 근거는 없으며, 실제 컷씬·공격 중단 연결은 해당 후속 Case에 남긴다.
- 제시된 다른 선택 사안들
  - 기존 명시적 차단은 조준도 멈추고 해제 후 물리 키를 다시 읽었다. 이번 대조 결과에 따라 대체한다.
