# Notion 기획 질문 답변의 선택 기록

주제: 2026-11-15 Q1~Q29의 제작 방향과 후속 문서 압축·성능 비교·완성 목표 요청의 선택 이유를 기록함.
- 현재 사양의 원본은 [GAME_SPEC](../../GAME_SPEC.md), 답변 원문 요약·처리 상태는 [QUESTIONS](../../QUESTIONS.md)에 둠. 아래 기능 ID는 GAME_SPEC의 해당 정의·케이스를 가리킴.
- 이 기록은 선택의 경위이며 구현·설치·성능 검증 완료 기록이 아님. 사용자가 제시하지 않은 이유는 `이유 미기록`으로 표시함.
- 우선 적용 후 비교할 항목은 [비교·보류 기록](../02_Hold/Notion_Comparisons_20261115.md)에 구분함. Q29의 최종 답변은 아래 선택 사안 15에 기록하며 Q16의 여러 backup 파일·별도 큐 가정을 대체함.

# 선택 사안 1 — 먼저 완성할 플레이 범위

- 선택: 경비 로봇의 원문 5패턴을 포함하여 입장부터 Ending까지 먼저 완성하고, 시간이 남으면 적 추가 후 dialogue를 다룸. 튜토리얼은 넣게 될 경우의 안내 순서로 남김. [B03·S01·S11·F-B07·F-S05·06](../../GAME_SPEC.md), [Q1·Q24](../../QUESTIONS.md).
- 이유: 이유 미기록. 시간 여유에 따른 추가 순서는 사용자가 직접 지정함.
- 제시된 다른 선택 사안들: Notion 6보스 일괄 포함, 기존 태엽 보스 중심, 데모 완료 문구로 종료.

# 선택 사안 2 — 이름 통일과 새 이름의 위임

- 선택: Q2의 A 이름을 채택하고, 이후 새 기능의 API·변수 이름은 AI가 정의한 뒤 사용자가 필요하면 변경함. Apply/Handle/Get/Set 형태와 간단한 public/static 표현을 선호함. [P01·P05·P06·P09·S02·S06 및 1장 공개 계약](../../GAME_SPEC.md), [Q2·Q4](../../QUESTIONS.md).
- 이유: 이유 미기록. 위 표현은 사용자 선호임.
- 제시된 다른 선택 사안들: Q2의 B 이름, 새 API마다 A/B를 일괄 선택하는 방식. 이번 위임은 기존 [정리 방식 결정의 선택 사안 2](Notion_Organization.md) 이후에 받은 변경임.

# 선택 사안 3 — 누락 책임과 세션 수명

- 선택: Q3의 보완안을 채택하되 생성은 StageManager, 맵 배치·구성·상호작용은 MapManager에 둠. Projectile 상속을 사용하며 Player/Boss는 세션 동안 재사용하고 CharacterBuff는 Character마다 둠. [P04·B01~05·S02·S03·S07](../../GAME_SPEC.md), [Q3·Q5](../../QUESTIONS.md).
- 이유: 이유 미기록. 직접 OnDie 연결의 이유와 성능 비교는 [H01](../02_Hold/Notion_Comparisons_20261115.md#h01-직접-ondie-구독과-중계자)을 따름.
- 제시된 다른 선택 사안들: 별도 Generator·문 클래스, 사망마다 Player 재생성, 중앙 CharacterBuff 관리. Map 책임 추가 분리는 보류 기록을 따름.

# 선택 사안 4 — 입력 의존과 차단 책임

- 선택: Input만 Player를 인지하고, 전역 차단과 Player 내부 행동 판정을 구분함. 현재 연출·이벤트 연결은 명시적 FSM 없이 이벤트 구독을 사용함. [P01~03·U07·S01·S13](../../GAME_SPEC.md), [Q6](../../QUESTIONS.md).
- 이유: Input이 Player를 인지하는 방향을 사용자가 명시함. 별도 선택 이유는 미기록이며 FSM 도입 필요성은 [H05](../02_Hold/Notion_Comparisons_20261115.md#h05-이벤트-연결과-fsm)를 따름.
- 제시된 다른 선택 사안들: Player가 Input을 참조해 차단까지 관리, 초기부터 명시적 Mode/State FSM 사용.

# 선택 사안 5 — Draw와 기존 Line의 관계

- 선택: 새 Line 확정 전에는 기존 Line을 유지하며 Q8의 입력·고정 길이·쿨타임 묶음을 채택함. 화면 밖 점을 제한하지 않고 벽 너머 Slash를 허용함. [P06~08·P10·F-P04~07](../../GAME_SPEC.md), [Q7·Q8](../../QUESTIONS.md).
- 이유: 이유 미기록.
- 제시된 다른 선택 사안들: 재Draw 시 기존 Line 제거, 다른 점 지정·초기화 키, 두 점 사이 가변 길이, 맵 영역 제한.

# 선택 사안 6 — 이동·공격·피해의 기준

- 선택: Q9의 4방향 우선안과 시간 분리, Q10의 A 행동·콤보·피격 규칙, Q11의 A 보호 구분 및 사각 판정을 채택함. Collider/CastNonAlloc·Gizmo 구현 시 Sephiria를 참고함. [P01~03·P05·P07~09·S08~10·U01](../../GAME_SPEC.md), [Q9~Q11](../../QUESTIONS.md).
- 이유: 이유 미기록. NonAlloc의 성능 우위는 측정하지 않았으며 8방향 검토는 [H03](../02_Hold/Notion_Comparisons_20261115.md#h03-4방향에서-8방향으로의-확장)을 따름.
- 제시된 다른 선택 사안들: 8방향 몸체 우선, Slash 중 슬로우, 공격 중 대시 취소, 피격 경직, 별도 회피 자원.

# 선택 사안 7 — 그로기·각성·잔류 공격

- 선택: 그로기 게이지 100에서 즉시 발동·0으로 소모하고 Q13의 각성 재적용·제거 규칙을 채택함. 그로기는 현재 패턴을 중단하되 기존 탄환·장판은 유지하며 몸 접촉 피해 없이 몸체 진입은 충돌로 막음. [P01·P08·B01·B04~06·S07·F-B04](../../GAME_SPEC.md), [Q12·Q13·Q25·Q28](../../QUESTIONS.md).
- 이유: 이유 미기록. 황금탄 반사의 현재안과 각도 방식 비교는 [H04](../02_Hold/Notion_Comparisons_20261115.md#h04-황금탄-반사-연출과-각도-물리)를 따름.
- 제시된 다른 선택 사안들: 게이지 발동·소모의 다른 시점, 기존 탄환·장판 제거, 몸 접촉 피해 적용, 각성 재적용 시 회복 생략.

# 선택 사안 8 — 재도전과 체크포인트

- 선택: Q14의 A 복원 묶음과 Q15의 F 입력·최초 1회 활성화를 채택함. [P04·B02·S04~06·F-P09·10](../../GAME_SPEC.md), [Q14·Q15](../../QUESTIONS.md).
- 이유: 이유 미기록.
- 제시된 다른 선택 사안들: 처치 위치를 새 시작점으로 저장, 재시작 확인 UI, HP만 복원, 사망 시 진행 되돌림, 범위 이탈로 활성화, 수정 재사용.

# 선택 사안 9 — 저장·복원과 실패 범위

- 선택: 진행률은 소비 측에서 계산하고 .sav 실패 시 .bak을 시도함. 저장을 기다리지 않고 진행하며 한 번 재시도 후 실패하면 LogError와 함께 해당 요청만 종료하고 다음 저장 이벤트는 정상 시도함. [S01·S05·S06·U03·F-S03](../../GAME_SPEC.md), [Q16·Q26](../../QUESTIONS.md).
- 이유: 이유 미기록.
- 제시된 다른 선택 사안들: 진행률 자체 저장, 전환마다 저장 성공 대기, 실패 후 세션의 저장 전체 중단. backup·실패 복원·앱 종료의 후속 확정은 선택 사안 15를 따름.

# 선택 사안 10 — Boss 패턴 선택

- 선택: 직전 패턴을 제외한 가중 추첨을 기본으로 하고 특정 상황의 강제 우선 패턴을 둘 여지는 남김. 구체 강제 조건은 아직 지정하지 않음. [B01·B04·F-B02](../../GAME_SPEC.md), [Q17·Q27](../../QUESTIONS.md).
- 이유: 최적화와 편향 회피를 고려한다는 사용자 설명. 실제 성능·분포 검증은 미실행임.
- 제시된 다른 선택 사안들: 최고 우선순위 후보들만 모아 균등 추첨. 미지정 강제 조건을 AI가 만들어 확정하지 않음.

# 선택 사안 11 — 맵 준비·카메라·설정

- 선택: Title+단일 MainWorld 전체 준비 후 시작, 자체 CameraController, Q19의 HUD·추적 기준과 Q20의 설정 범위를 채택함. [S01~03·U02·U05~07](../../GAME_SPEC.md), [Q18~Q20](../../QUESTIONS.md).
- 이유: 이번 답변의 별도 이유 미기록. 단일 맵에 대한 과거 원문 이유는 GAME_SPEC D04에 보존하며 이번 답변의 새로운 이유로 바꾸지 않음.
- 제시된 다른 선택 사안들: 구간 교체·여러 Scene/스트리밍, Cinemachine, Boss 방향 기본 카메라 보정, Boss 사망 시 Player HUD 숨김.

# 선택 사안 12 — 비동기 도구의 적용 범위

- 선택: UniTask는 저장과 Title UI 초기화에만 사용하고 나머지는 코루틴을 사용함. [S05·S06·U03·U07 및 3.4](../../GAME_SPEC.md), [Q21](../../QUESTIONS.md).
- 이유: 세피리아의 사용처 구분을 참고했다는 사용자 설명. 실제 추출 코드에서 확인한 범위와 한계는 GAME_SPEC 3.5에 기록함.
- 제시된 다른 선택 사안들: 저장·로딩·연출 전체에 UniTask 사용, 표준 Task와 Awaitable/코루틴 조합. 설치·연결은 미실행임.

# 선택 사안 13 — FMOD

- 선택: 효과음과 학습 목적으로 FMOD를 사용하며 비상업 전시를 대상으로 함. [U08 및 3.4](../../GAME_SPEC.md), [Q22](../../QUESTIONS.md).
- 이유: FMOD 학습 목적을 사용자가 명시함.
- 제시된 다른 선택 사안들: AudioSource·AudioMixer, 음악 연출 확정 후 도구 선택. 설치·연결·사용 조건 충족 검증은 별개임.

# 선택 사안 14 — Unity 계열과 DebugController

- 선택: 선택 plugin의 2022.3 전용 제약이 없으면 Unity 6.3 LTS를 쓰는 조건을 채택함. 확인된 선택 도구에는 해당 제약이 없어 6.3 LTS 계열로 결정함. DebugController는 제출 코드에 포함하되 개입은 Editor로 제한함. [S12 및 3.4](../../GAME_SPEC.md), [Q23](../../QUESTIONS.md).
- 이유: plugin 호환을 버전 선택 기준으로 사용하며 DebugController는 AI 효율 향상에 활용한 내용을 명시하기 위함. 그 외 이유 미기록.
- 제시된 다른 선택 사안들: 2022.3 전용 plugin이 있을 경우 2022.3, 최초 제안의 Unity 6.0 LTS, DebugController를 제출에서 제외. 정확한 패치 후보·공식 확인 근거는 GAME_SPEC에서 관리하며 설치 완료로 기록하지 않음.

# 선택 사안 15 — 단일 backup과 저장 검증·종료

- 선택: `Save(backupCount)` 인자는 유지하되 사용하지 않고 .bak 1개를 갱신함. .sav 기록/덮어쓰기 후 무결성을 검사하고 실패 시 1회 재시도함. 다시 실패하면 기존 .bak을 .sav로 복원한 뒤 LogError와 함께 해당 요청을 종료하며 다음 저장 이벤트는 정상 시도함. 정상 저장은 검증된 .sav를 .bak으로 복사하고, 앱 종료는 진행 중 저장·복구 완료 후 수행함. [S01·S05·S06·F-S03](../../GAME_SPEC.md), [Q29](../../QUESTIONS.md).
- 이유: 이유 미기록.
- 제시된 다른 선택 사안들: Q16의 N개 backup 별도 큐, Q29의 최대 보관 개수/한 번에 생성할 개수 해석, 저장 완료를 기다리지 않는 앱 종료. 최신 Q29 답변으로 위 가정을 대체함. 구현·복구 검증은 아직 미착수임.

- 이유: 질문 문단을 압축해 정리해 달라는 사용자 요청.
- 제시된 다른 선택 사안들: 반복 질문·폐기 선택지·권고 문단을 본문에 계속 유지하는 기존 방식.

# 선택 사안 17 — Profiler로 비교하고 결과에 따라 선택

- 선택: [GAME_SPEC 3.1.1](../../GAME_SPEC.md)에 최적화 비교 후보와 동일 조건·측정값·채택 기준을 마련함. 기능이 동작한 뒤 Unity Profiler로 비교하여 성능이 더 나은 안을 선택하며, 비교 방법의 세부 구성은 AI가 정리한 실험안임.
- 이유: 프로젝트 결과의 선택 논리를 실제 측정 근거로 강화하려는 사용자 목적.
- 제시된 다른 선택 사안들: 예상만으로 성능 우위를 주장하거나 서로 다른 행동/연출을 단순 속도로 선택하는 방식은 채택하지 않음. 측정과 선택은 아직 미실행임.

# 선택 사안 18 — 콘텐츠·연출 중심의 완성 목표

- 선택: 세부 시스템 조정을 제외하면 Boss 콘텐츠와 FX·VFX 등 연출 추가에 집중할 수 있는 기반을 현재 완성 목표에 포함함. 구체 완료 조건은 [GAME_SPEC 상단 완성 목표](../../GAME_SPEC.md)에 둠.
- 이유: 후속 제작을 Boss 콘텐츠·연출 추가에 집중할 수 있게 하기 위함.
- 제시된 다른 선택 사안들: 없음. 사용자가 직접 지정한 목표이며, 목표 기록을 실제 기반 완성으로 처리하지 않음.
