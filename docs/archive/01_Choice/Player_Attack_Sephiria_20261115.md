# 선택 주제
주제: F-P03 단일 무기의 공격 요청·허용·실행 책임 분리

# 선택 사안 1
- 선택: 사용자 확정 — Input은 공격 입력 사실만 전달하고 PlayerCharacter가 공격 가능 여부와 조준 좌표를 결정한다. AttackController는 해당 방향의 무기 애니메이션·공격 판정·피해 적용을 담당한다.
- 이유: 사용자가 제시한 Sephiria의 입력·캐릭터·무기 책임을 하나의 고정 무기를 쓰는 현재 규모에 맞추려는 요청. 별도 이유 미기록.
- 유지: 기존 Q10의 공격 중 느린 이동·대시 전환 금지와 홀드 반복·3단 콤보·AS 반영을 따른다. 이동량 계산은 Character.Update, 물리 적용은 Body.FixedUpdate가 계속 담당한다.
- 채택: PlayerInputController.HandleOnFire의 입력 해제·차단 처리, PlayerAvatar.StartAttackClientside의 행동 허용 확인, WeaponControllerSimple·WeaponSimple과 실제 파생 무기의 공격·판정 흐름을 실제 소스로 확인해 적용한다.
- 생략: 무기 교체·여러 무기별 파생 계층·네트워크·아이템 배율은 도입하지 않는다. 현재 AttackController 하나가 고정 무기를 실행한다.
- 구현값: 공격 시간·판정 구간·감속·콤보 시간·3타 배수·범위는 Inspector에서 조정할 초기 튜닝값이며 사용자 확정 밸런스로 기록하지 않는다.
- 기준 원본: 현재 API·수치·호출 흐름·검증·남은 아트 연결은 [GAME_SPEC 2.1.3](../../GAME_SPEC.md#213-f-p03-일반-공격-구현확인과-sequence-diagram), 실제 참고 파일은 [REFERENCE_CODE_MAP](../../REFERENCE_CODE_MAP.md)을 따른다.

# 선택 사안 2 — 시작 허용과 진행 중단의 분리
- 선택: 사용자 확정 — 사망·컷씬·준비 여부 등 공통 행동의 시작 허용은 PlayerCharacter에서만 판단한다. AttackController는 공격 중 여부·쿨타임·공격 계산 수치만 검사하고, 이미 진행 중인 공격은 사망·컷씬 진입 사건을 CancelAttack에 연결해 중단한다.
- 이유: 같은 공통 상태를 캐릭터와 무기가 중복 검사하는 비효율을 없애고 각자의 책임과 진행 중 공격의 중단 경로를 명확히 하려는 요청.
- 반영: Character의 실제 치명 피해는 기존 OnDie를 발행하고, IsCutScene의 false→true 전환은 OnCutScene을 한 번 발행한다. PlayerCharacter가 Awake에서 두 사건을 자신의 CancelAttack에 연결하고 제거 때 해제해 공격 유지 의도와 무기 진행·판정·콤보를 함께 정리한다. IsCutScene의 기존 직렬화 이름을 보존한다.
- 경계: 저장 체력 복원 InitializeHealth와 IsDead의 직접 대입은 사망 발생 통지가 아니다. 실제 사망 연결은 ApplyDamage의 치명 전이로 검사한다. 일시정지는 취소 사건이 아니며 남은 공격 시간을 보존한다.
- 원작 적용: PlayerAvatar의 CanMove 시작 허용과 UnitAvatar.ForceDie→CancelCurrentAction→무기 CancelAction의 진행 중단을 참고했다. 원작의 컷씬은 입력 차단으로 제어하므로 우리 OnCutScene 진입 이벤트는 현재 게임에 맞춘 변형이다.
- 추가 수정: 피해 콜백에서 사망·컷씬이 시작되면 열린 CollisionBox와 후속 무기 갱신도 즉시 끝내 다음 수신자 피해와 취소된 자세의 재적용을 막는다.

# 선택 사안 6 — 기준보다 높은 FPS에서도 같은 재생 시간
- 선택: 사용자 요구(2026-11-16) — 실행 환경이 제작 기준 FPS보다 높더라도 공격/VFX 속도에 문제가 생기지 않게 한다.
- 이유: FPS 기준이 달라지는 환경에서도 같은 속도로 보이길 바라는 요청.
- 적용 기준: 제작 설명은60fps 타임라인으로 통일하고 Unity 실제 재생은 경과 시간에 따른다. 한 번의 Update마다 한 장을 진행하거나 초과 시간을 버리는 타이머를 사용하지 않는다. 렌더FPS 상한 설정으로 문제를 우회하지 않는다.
- 원본: GAME_SPEC3.3.8. 이번에는 기준을 기록했으며 VFX 런타임 구현·다중FPS 계측을 수행한 사실로 기록하지 않는다.

# 선택 사안 7 — 이미지와 노출 프레임은 사용자가 지정
- 선택: 사용자 요청(2026-11-16) — 원작 검기 이미지를 기반으로 Aseprite에서 일부 수정할 수 있게 준비하고, 이후 제공하는 이미지가 원하는 공격 프레임에 나오게 연결한다.
- 이유: 사용자는 원작을 그대로 복제하지 않도록 이미지 일부를 수정하면서 작업량을 최소화하려고 한다.

- 재생 지시: Aseprite미리보기/원작0.2초는 자동확정하지 않는다. 이미지 순서와 등장/유지 프레임은 이후 사용자 지시에 맞추고 실제 실행속도는 프레임률 독립 기준을 유지한다.

# 선택 사안 8 — 2타의 흰색 중심과 강한 끝부분 색
- 선택: 사용자 요청(2026-11-16) — VFX 작업 분기에서1타와2타의 팔레트를 구분한다. 현재 Aseprite의 흰색 베이스를 유지하면서 끝부분 색을 바꾼다.
- 이유:2타가 더 강한 공격으로 느껴지길 바라는 요청.
- 제작안:1타 native를 보존하고 별도2타 native에 옅은 금색·금색·주황·붉은 주황을 넣었다. 첫 이미지의 약73%는 흰색으로 유지하며 모든 프레임의 형태·알파·피벗은 같다. 구체 색상은 AI 제작안이며 사용자 최종 선택과 구분한다.
- 현재 원본과 비교: [편집 작업실](../../../art/archive/weapon/greatsword-vfx-edit/README.md)·GAME_SPEC3.3.8. Unity 코드/재생프레임 연결은 이번 팔레트 작업에 포함하지 않는다.

# 선택 사안 9 — 끝의 의미를 최외곽으로 정정·강조색1~2개
- 선택: 사용자 정정(2026-11-16) — 끝은 호가 진행되는 끝부분이 아니라 그려진 호의 가장 바깥 부분이다. 흰색 베이스에 강조색1개또는2개만 사용하고 애매하면 원작의 강화 검기를 참고한다.
- 이유: 하얀색만 사용할 때보다 강한2타로 느껴지길 원한다. 이전 진행 끝부분5색 해석은 이 요청으로 대체됐다.
- 반영: 흰색+금빛 주황`#FFB23C`의2색으로 단순화하고 최외곽 약3px띠에만 강조색을 넣었다. 색상은 제작안이며 형태·알파·피벗·1타는 유지한다.
- 참고: 원작3티어빙계대검의 실제 공격/FX연결과 흰색+옅은청색1강조색PNG를 확인했다. 구성만 참고했으며 현재색/최외곽배치를 원작과동일하다고기록하지 않는다. 현행원본은 GAME_SPEC3.3.8과작업실을 따른다.

# 선택 사안 10 — 우리3타의 푸른 X·꼬리 소멸·큰 피해1회

- 제작안: 새두곡선을교차하고흰색/옅은하늘색/푸른색공통팔레트를사용했다. 중심먼저소멸한뒤양쪽꼬리만남는4이미지이며기존1·2타원본은보존한다. 현행파일은GAME_SPEC3.3.8과 [작업실](../../../art/archive/weapon/greatsword-vfx-edit/README.md)을따른다. 모양/색의최종미술선택·실제게임무기모션/재생프레임연결은후속이다.

# 선택 사안 11 — 탑다운 호 교차와 서로 다른 연한 색
- 선택: 사용자 정정과 첨부 스케치(2026-11-16) — 기존 호형 검기 두 개를 반전해 겹치고 중앙에서 위아래 관계를 바꾼다. 완전한 원형보다 약간 치우친 모양으로 X 느낌을 강화한다. 두 검기는 서로 다른 연한 색을 쓴다.

- 제작안: 기존4장의 호를 전단/압축·반대 기울임·위치 차로 교차하고, 연하늘/연보라로 구분했다. 중앙 위쪽A/아래쪽B가 앞에 보이도록 덮개 레이어를 두었다. 현재 치수·색은 제작안이며 실제 피해1회·꼬리마지막 방침은 유지한다.
- 현행: GAME_SPEC3.3.8과 작업실. 실제 게임 연결·최종 미술 선택은 후속이다.

# 선택 사안 8 — Player 애니메이션 재생 구조 이관
- 선택: 사용자 확정(2026-11-16) — Sephiria의 실제 Player 애니메이션 재생 구조를 분석하고 우리 Player의 몸체·무기 재생에 맞춰 이관한다.
- 이유: 남은 시간이 부족한 상황에서 구현 리스크를 줄이기 위해 이미 사용되는 레퍼런스의 책임 분리와 재생 방식을 활용하려는 선택.
- 채택: 몸체는 상태별 Sprite 데이터와 재생기를 분리하고, 무기 위치·회전은 별도 Unity Animator/클립으로 재생한다. 기존 확정 아트·공격 시간/판정·대시·후진·피격 보호·생명주기·Draw/Slash 정책은 보존한다.
- 차이: 고정 무기·싱글 플레이에 필요 없는 코스튬/무기 교체·RPC·전역 애니메이터 관리자는 도입하지 않는다. 원작 Timer의 초과시간 폐기를 복제하지 않는다. 원작3타는 전용 몸체 Swing10장을 사용하지만 우리 공격 몸체 아트가 없어 무기 궤적만 적용하고 몸체 요청 이벤트는 생략한다.

# 선택 사안 29 — 무입력 공격 전진 감소와 아래 대기 검 정렬
