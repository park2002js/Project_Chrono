# 선택 주제
주제: F-P04 Draw의 전용 입력·편집·표현·복구 책임 분리

# 선택 사안 1
- 선택: 사용자 확정 — 대시·일반 공격처럼 각자의 역할을 분명히 나누고 Draw에서는 입력 자체를 전환한다. 점·Line의 VFX는 최신 연출을 반영하기 쉽게 구성하고 현재는 임시 표현을 사용한다.
- 이유: 행동별 책임을 명확히 유지하고 이후 VFX 교체를 쉽게 하려는 요청. 별도 이유 미기록.
- 반영: Input Actions의 Player/Draw 맵을 교체하고 Character는 공통 시작 허용, Skill은 편집·확정 데이터·전환 조정, LineDrawer는 점과 고정 길이 기하를 담당한다. GameManager의 Draw 정지는 일반 정지와 별도로 합산한다. UI·Camera·Rendering·DrawVfx는 표현과 복구만 담당한다.
- 유지: Q7의 기존 Line 보존·새 확정 때만 교체, Q8의 Shift/M1/R/F, Q9의 게임 시간 정지와 unscaled 표현, Q10의 공격 중 Draw 금지, Q19의 Player·커서 가중 중심을 따른다.
- VFX 교체: 점·미리보기·확정 선의 GameObject 프리팹을 Inspector 슬롯으로 지정한다. 선은 로컬 X 길이1·Y 폭1 규격을 사용한다. 임시 LineRenderer의 폭 보정은 프리팹 내부 DrawLineVfx에 한정한다. 연결 도구는 기존 자산·지정한 최신 슬롯을 보존한다.
- 경계: 슬롯 교체는 다음 Player 생성 때 반영하며 실행 중 hot-swap 시스템은 추가하지 않는다. 이번 점 편집·확정은 F-P04 전환을 확인하는 연결이며 F-P06 수명/만료와 F-P07 Slash 피해를 완료한 것은 아니다. 실제 VFX·음향·fade와 수치 조정은 후속이다.
- 현재 기준: 실제 API·초기화 순서·검사 결과·시퀀스와 참고 코드는 [GAME_SPEC 2.1.4](../../GAME_SPEC.md), [REFERENCE_CODE_MAP](../../REFERENCE_CODE_MAP.md)을 따른다.

# 선택 사안 2
- 선택: 사용자 확정 — 확정 Line의 유일한 원본은 PlayerCharacter.CurrentLine에 보관하고 SkillController가 Draw의 확정 값을 받아 저장·수명·예고·만료 표현을 관리한다. 이번 작업에서 F-P05 점 편집과 F-P06 수명·만료를 함께 진행한다.
- 이유: 데이터 보관과 수명 관리의 책임을 명확히 하려는 요청. 범위를 함께 진행하는 별도 이유 미기록.
- 변경: 기존 사안1·Q7의 SkillController 원본 보관 설명을 이번 요청으로 대체한다. Draw 진입·R 초기화·취소에서는 기존 원본을 유지하고 새 확정에서만 교체한다. LineDrawer는 임시 점과 기하만 관리한다.
- 반영: Skill의 같은 게임 시각 갱신 창구에서 쿨타임·기존 소멸 표현·현재 Line 수명을 진행한다. 자연 만료는 원본 해제·짧은 대기·전용 VFX를 한 번 발생시키며 Draw·일반 정지와 Skill 비활성 중에는 수명을 보존한다. 수명 후반 깜박임은 만료에 가까울수록 빨라진다.
- 소비 경계: TryConsumeLine은 입력 시점에도 만료를 재확인한다. 유효한 Line만 한 번 인계하고 원본·수명을 비우며 일반 Draw 대기를 적용한다. 자연 만료 VFX는 소비에서 재생하지 않는다. F-P07의 Slash 시작 허용·공격·판정·피해는 후속 작업이다.
- 표현·수치: 점·미리보기·보유 선·만료 선은 교체 가능한 프리팹을 사용한다. 수명8초·예고 구간35%·점멸 주기0.5→0.08초·만료 표현0.25초·소비 후 대기3초는 Inspector의 초기 튜닝값이며 사용자 밸런스 확정이 아니다.
- 현재 기준: 점 편집은 GAME_SPEC 2.1.5, 수명·만료·소비와 실제 검증 결과는 GAME_SPEC 2.1.6을 따른다. Notion은 기능별 토글로 기록하며 미리보기 조작·확인은 체크하지 않는다.

# 선택 사안 3
- 선택: 사용자 확정 — 최종 Draw VFX에는 두 점 오브젝트를 굳이 배치하지 않는다. 첫 점의 위치는 조준점 아이콘으로 알리고 두 번째 점이 정하는 방향은 커서에 따라 계속 방향을 바꾸는 선으로 표현한다.
- 이유: 이유 미기록. 현재 임시 두 점 입력·기하의 제거 요청이 아니라 완성 시점의 표시 방향 기록 요청으로 해석한다.
- 임시 Slash 표현: 사용자 확정 — Line 소비 때 원래 Line보다 얇고 긴 선이 같은 경로를 따라 번쩍이도록 한다. 마지막 정지 시점의 판정과 복구에 맞춰 성공 표현을 시작하며 실제 판정의 길이·폭은 확장하지 않는다.
- 경계: 정확한 아이콘·Particle/검기 모양·음향과 Inspector의 연출 시간·배율은 최종 아트/튜닝으로 남긴다. F-P07 동작과 실제 검사 상태는 GAME_SPEC 2.1.7을 따른다.

# 선택 사안 4
- 선택: 사용자 확정 — 일반 카메라 추적 기준을1초에서0.5초로 줄이고 Draw의 커서 추적 기준은0.3초로 분리한다. PlayerCharacter.CurrentLine은 internal set 프로퍼티 대신 public Line? CurrentLine 공개 필드로 둔다.
- 이유: Draw에서 마우스 움직임에 빠르게 대응하려는 요청. 공개 필드에 대한 별도 이유 미기록.
- 반영: GameCamera.FollowDuration/DrawFollowDuration과 기존 WorldCamera 프리팹 값을 함께 갱신한다. 두 값은 SmoothDamp의 반응 기준이며 정확한 도착 시각 보장은 아니다. 확정·해제 시 수명과 VFX를 함께 갱신하는 기본 호출은 SkillController.SetLine을 유지한다.
- 책임 경계: 후속 사용자 확정에 따라 카메라는 PlayerCharacter의 상태를 조회하지 않는다. SkillController가 Draw 진입/종료·Slash 모드/목표를 명시 요청하고 Camera는 자기 표시 모드로 일반/Draw 기준시간을 자동 선택한다. 두 시간은 독립 공개 변수로 보관한다.

# 선택 사안 5
- 선택: 사용자 확정(2026-11-16) — pixel/image FX의30° 비교에서 image FX 방식을 선택해 현재 Draw에 적용한다. 두 입력 점은 시각적으로 남기지 않는다.
- 이유: 사용자가 비교 결과에서 image FX가 더 좋다고 평가했다. 구체적인 미술 선호 이유는 미기록.
- 제시된 다른 선택 사안: 계단형 픽셀 경계의 선, 매끄러운 이미지 텍스처와 잔광의 선.
- 변경: 사안3의 향후 표시 방향과 임시 두 점 유지 상태를 이번 적용 요청으로 갱신한다. 논리 첫 좌표·두 번째 방향 선택, 고정 길이/폭, R/F/Shift·기존 Line 보존은 유지한다.
- 반영: DrawVfx의 점 슬롯·객체·생성/표시를 제거하고 미리보기/확정/만료 선에 이미지 FX 재질을 연결한다. SlashFlash의 기존 재질·실제 피해 기하는 유지한다.
- 구분: 방식·점 미표시는 확정이며 PNG96×64·흰/청록 세부·알파와 폭은 선택한 스타일에 맞춘 현행 적용값이며 별도 수치 확정과 구분한다. 실제 구현/확인 상태는 [GAME_SPEC3.3.13](../../GAME_SPEC.md#3313-draw-이미지-fx-적용--draw-line-image-r01)을 따른다.

# 선택 사안 6
- 선택: 사용자 요청(2026-11-16) — Draw 선의 표시 두께를 강화하고 LineLength 값 증가와 실제 표시 길이가 연결되며 Draw 종료 뒤 밝은 바닥에서도 선이 잘 보이도록 한다. 검은 고정 외곽/단색 띠는 이 요청을 AI가 잘못 해석한 제작안으로 후속 반려됐다.
- 이유: 선의 가독성과 설정 길이의 실제 표시 반영을 개선하기 위한 요청. 정확한 두께 배율·색상 수치는 요청에서 따로 확정하지 않았다.
- 당시 AI 적용안·이후 반려: 표시 전용 WidthMultiplier2f·Slash1f·Line.Width0.25와 청록 중심#11CEE9/어두운 테두리#073044의 R02 PNG를 적용했다.23검사 성공은 기술 확인일 뿐 사용자의 미술 승인이 아니다. 현행은 사안7/R03을 따른다.
- 길이 계약: Begin에서 이번 편집의 LineLength를 고정하고 표시/확정/Slash가 같은 Line.Length를 사용한다. 설정 변경은 다음 Draw부터 적용하며 기존 Line을 소급 변경하지 않는다.6→12는 검증 입력이지 기본값12 확정이 아니다.
- 유지: 점 미표시·두 클릭/R/F/Shift·원본/수명·기존 판정폭을 보존한다. 표시 확대를 피해 영역 확대로 처리하지 않는다.
- 구분: 코드·자산 반영과 실제 확인 상태는 [GAME_SPEC3.3.13 R02](../../GAME_SPEC.md#r02-표시-두께길이-연동확정선-대비-보완--draw-line-image-r02)를 따른다.


# 선택 사안 7
- 선택: 사용자 정정(2026-11-16) — 처음 선택한 IMAGE FX의 광원·부드러운 빛 번짐을 유지한 채 FX 자체를 더 두껍게 한다. R02의 단색 띠·검은 고정 테두리는 의도와 달라 반려한다.
- 이유: 사용자가 원한 발광 효과를 검은 외곽의 굵은 선으로 잘못 해석했기 때문이다. R02의23검사 성공은 기술 동작 이력이며 미술 승인과 무관하다.
- 적용 방향: 흰 발광 중심·cyan/aqua·푸른 코로나·부드러운 외광의 투명 발광 리본으로 광원 몸체/halo를 넓힌다. 내장 image_gen 결과·정확한 프롬프트를 R03에 보존하고 같은 게임 PNG 경로/GUID에 반영한다.
- 적용값: R03 발광 텍스처1536×1024 RGBA, Preview/Confirmed/Expired 표시3f·Slash1f·판정폭0.25. 기존 길이 snapshot/표시·Slash 연동·점 미표시·입력/수명은 유지한다.
- 후속 사용자 확인: R03 발광 스타일을 좋다고 확인했으며 중앙 스타일을 유지한 양끝 마감 수정을 사안8로 요청했다. 기술 검사와 사용자 확인을 구분한다. 실제 실행/시각 확인 상태는 [GAME_SPEC3.3.13 R03](../../GAME_SPEC.md#r03-발광-광원부드러운-번짐-복원--draw-line-image-r03)을 따른다.


# 선택 사안 8
- 선택: 사용자 요청(2026-11-16) — R03은 좋다고 확인했으나 빨대처럼 잘린 시작/끝을 중앙처럼 오라가 감싸도록 수정한다. 중앙 발광·두께·색은 유지한다.
- 이유: 잘린 양끝의 인상을 없애고 중앙과 같은 부드러운 발광 마감으로 연결하려는 요청.
- 적용안: 양끝의 흰 중심을 짧고 둥글게 닫고 바깥 cyan/blue halo를 더 이어 투명 경계로 감싼 R04 PNG를 같은 게임 경로/GUID에 반영한다.
- 유지:1536×1024 RGBA·표시3배·기존 런타임 API·Stretch·길이 snapshot·판정폭0.25·점 미표시. 고정 월드 반경 캡 시스템은 추가하지 않는다.
- 구분: UV 끝 페이드로 가시 흰 중심만 안쪽에서 닫히며 data/메시 끝점은 유지한다. R03 스타일 긍정과 새 R04 양끝 마감 확인은 별개이며 실제 결과는 [GAME_SPEC3.3.13 R04](../../GAME_SPEC.md#r04-양끝-둥근-광원광륜-마감--draw-line-image-r04)를 따른다.


# 선택 사안 9
- 선택: 사용자 요청(2026-11-16) — 같은 Draw FX가 alpha로 투명해졌다 원본으로 돌아오기를 반복한 뒤 그대로 빛 조각으로 분해된다.
- 이유: 기존 bool 점멸·주황 tint/폭 축소 대신 선택한 FX 자체의 연속 투명도 변화와 분해를 원한 요청.
- 당시 반영·후속 반려: alpha 왕복/논리 수명 유지와 R05 shader SetDissolve를 구현·23검사했다. 사용자는 alpha 왕복은 유지하되 제자리 noise/UV로 줄어드는 분해 대신 실제 입자의 이동/증발을 요청했다. 실제 파티클 이동의 구현/승인은 사안10/R06에서 구분한다.
- 적용값: 총수명8초·경고 비율0.35·Slow0.5/Fast0.08초 유지, 분해0.65초. 경고 구간 마지막12%는 원본 alpha로 연결한다. 캡처용 수명2.4초·경고0.9·주기0.4/0.08초는 검사 입력이며 기본값 변경이 아니다.
- 유지: 길이·판정폭0.25·표시3배·점 미표시·정지/교체/사망 정리와4개 객체 재사용. 원작에서는 시간 비율/재생 수명만 참고하고 연속 alpha·shader 분해는 직접 구현한다.
- 구분: R05의 코드 반영·실제 실행·사용자 미술 확인은 [GAME_SPEC2.1.6](../../GAME_SPEC.md#216-f-p06-line-원본수명만료-vfx-연결)·[3.3.13 R05](../../GAME_SPEC.md#r05-연속-알파-경고원본-fx-분해)를 따른다. 별도 SlashPresentation 진행은 변경하지 않는다.


# 선택 사안 10
- 선택: 사용자 정정(2026-11-16) — alpha 왕복은 유지하고 실제 파티클 조각이 선에서 떨어져 사방/위로 퍼져 올라가다 사라진다. 물방울처럼 제자리에서 줄어드는 R05 noise/UV 분해는 반려한다.
- 이유: 제자리 shader 소멸을 실제 조각의 이동/증발 대신 적용한 해석이 사용자 의도와 달랐기 때문이다.
- 구현 방향: DrawEvaporationVfx/ParticleSystem을 씬 루트에 한 번 준비해 재사용하고 같은 R04 texture의 별도 입자 재질을 사용한다. 원본 FX는 초기25% alpha로 넘기고 입자는 크기를 고정한 채 실제 위/양옆 이동과 수명 alpha로 사라지게 한다.
- 적용값·확인: ExpiryDuration1.3초·길이1당12조각(최대768), 실제 입자 이동/크기 고정/alpha 소멸과 같은 scaled clock·정지/교체/사망 정리를 구현했다. 길이/판정폭0.25·표시3배·점 미표시를 유지하고 격리23검사·실제72입자 추적/영상으로 확인했다. 새 결과 사용자 미술 승인과 최신 원본 전체 실행은 별도로 구분한다.
