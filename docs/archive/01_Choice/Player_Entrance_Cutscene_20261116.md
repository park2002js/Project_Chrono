# 선택 주제
주제 : 새 게임 최초 입장의 복도 확장과 실제 Player 보행 연출
- 2026-11-16 사용자는 시작에서 보스전 입구까지 약3배 길이의 복도와, 아래에서 위로 걸어와 멈춘 뒤 조작 권한을 인계하는 연출을 요청했다

# 선택 사안 1 — 실제 Player와 컷씬 권한
- 선택 : 생성된 실제 Player를 TutorialController가 컷씬 권한으로 이동시키고 목표에서 정지·사용자 조작 인계
- 이유 : 체크포인트에서 나타나는 방식 대신 실제로 걸어 들어온 모습을 만들도록 사용자가 지정
- AI 구현 선택 : 일반 입력과 별도의 컷씬 이동 목표를 두되 같은 Player의 속도·Body 충돌·몸체 모션·발소리 경로를 사용한다. Transform 보간이나 별도 컷씬 캐릭터는 사용하지 않는다
- 범위 : 최초 입장 걷기만 구현. 이동/공격/회피 안내·대사·전체 튜토리얼 완료를 뜻하지 않는다

# 선택 사안 2 — 재생 조건
- 선택 : 새 게임 최초 진입에만 실행하고 이후 계속·사망 부활은 체크포인트 유지
- 이유 : 사용자가 질문지에서 이 선택지로 답변. 추가 이유 미기록
- 제시된 다른 선택 사안 : 시작 체크포인트 슬롯의 월드 진입마다, 진행도와 관계없이 모든 월드 진입마다
- AI 구현 선택 : 새 저장에 EntranceCompleted=false를 넣고 정상 목표 도착 뒤 true와 Save 요청. 중단은 미완을 유지한다. 표식이 없는 기존 저장은 도입을 반복하지 않으며 기존 진행을 보존한다

# 선택 사안 3 — 길이 기준
- 선택 : 게임 시작부터 첫 보스전 입구까지 약3배 길이
- 이유 : 사용자가 길이 비율을 지정
- AI 적용 기준 : 현재 눈에 보이는 첫 입구문의 물리 중심Y4.5와 시작Y1.4의3.1world를 기준으로 남쪽6셀을 더한다. 새 출발Y−4.6부터 문까지9.1world로 약2.94배이며 기존 시작Y1.4를 조작 인계점으로 사용한다
- 기존 방·문·수정·체크포인트 위치는 보존하고, 자동 보행 경로와 실제 부활 체크포인트를 분리한다. 남쪽 카메라 경계만 확장한다

# 현재 상태
- 코드·세 프리팹 연결과 격리7검사/실제 입장 영상을 확인하고 원본에 GUID를 보존해 반영했다. 도착 오차0·입력 인계·정상 완료 저장/구저장 호환·중단 재시도를 확인했으며 원본 직접 Play와 제출 빌드는 미실행이다
- 구현·연결·확인 결과는 [GAME_SPEC](../../GAME_SPEC.md)의 S11/F-S05 및 F-S01을 따른다

# 선택 사안 4 — 화면 밖에서 중앙까지의 입장 정정
- 선택 : Player가 화면 아래 바깥에서 들어와 카메라 중앙에 도착한 뒤 조작 가능, 맵 세계 밖 이동은 불가
- 이유 : 사용자가 기존 입장 영상 뒤 화면 기준의 시작·인계 조건을 직접 정정
- AI 구현 선택 : 도착점에 카메라를 고정하고 로딩 중 위쪽 몸체/검 자세를 미리 반영한다. 출발점Y−5.6은 기존 남쪽 경계Y−6 안에 있으며 줌5.625/도착Y1.4의 화면 하단Y−4.225보다 몸체·검 전체가 아래에 위치한다
- 적용 : 기존6행 확장은 유지하고 보행 거리는7world로 변경. 도착 뒤에는 기존 Player 추적으로 복구하며, 일반 추적의 기준인 Player root를 viewport(0.5,0.5)로 판단한다. Sprite 시각 중심의 피벗 차이는 구분한다
- 기존의 새 게임 최초1회·계속/부활 체크포인트·정상 완료 저장 계약은 유지한다. R01의 생성 직후 보이는 화면/추적 카메라와 구분해 R02로 검증한다
- R02 확인 : 실제 최초 몸체/검 viewport가 모두0 아래이며, 도착 root는(.5,.5)·미세 이동 오차0이다. 걷기/대시의 남/좌/우 경계와 카메라 정상/중단 복구를 포함한7검사를 확인하고 원본 Map 마커만 GUID 보존 출판했다. 최종 영상과 범위는 R02 기록을 따른다

# 선택 사안 5 — 문이 보이지 않는 복도에서 입장 종료
- 선택 : 복도를 더 늘리고 입구문이 보이지 않는 곳에 카메라 중심을 둔 뒤, Player가 그곳까지 오면 연출 종료
- 이유 : 사용자가 R02 입장 뒤 화면에 문이 보이지 않도록 길이와 도착점을 정정
- AI 적용 기준 : 남쪽 보충12행·세계하한Y−12, 출발Y−11.6/독립 도착Y−4.6의7world 보행. 기본 줌5.625에서 화면 상단은Y1.025이고 문 이미지의 하단Y3보다1.975world 아래라 전체 문이 화면 밖에 놓인다
- 기존 저장 체크포인트Y1.4와 도착 marker를 분리해 계속/부활 위치를 바꾸지 않는다. 새 게임 최초1회/화면 밖 시작·고정 카메라·중앙 인계/완료 저장 계약은 유지한다
- R01/R02 길이·좌표·영상은 이전 이력으로 보존하며 R03의 실제 확인 결과는 GAME_SPEC F-S05와 새 영상 기록을 따른다
- R03 확인 : 같은 Unity6000.3.21f1의 격리7검사에서 입장 내내 문 전체의 최소 viewportY1.1755556>1·Player root 중앙(.5,.5)·입력/저장/중단/구저장·걷기/대시 경계를 확인했다. Map·Camera만 GUID 보존 출판/post4파일 동일, [실제 영상](../../../art/archive/map/player-entrance-r03/README.md)·Notion 기존 Class/4Case 저장을 마쳤다. 원본 직접 Editor Play·제출 빌드는 미실행이다
