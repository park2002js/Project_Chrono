# 선택 주제
주제: F-P08 피격·보호 사건과 빨강/원본색 표시의 책임 분리

# 선택 사안 1
- 선택: 사용자 확정 — 상태를 발생시키는 쪽은 상태가 변했다는 것만 알리고 구독자가 자기 역할을 처리한다. 완료 시 Notion의 클래스 역할과 Sequence Diagram을 함께 갱신한다.
- 이유: 이유 미기록
- 반영: Character.ApplyDamage는 피해 허용·HP/사망 확정과 OnDamaged/OnDie를 담당한다. Player는 Awake0에서 자기 OnDamaged를 먼저 구독해 피격 보호 기한을 갱신하고 OnHitProtectionChanged로 진입/종료를 알린다. Rendering은 Awake200 이후 해당 사건에 구독해 자기 표시만 처리한다. 피해 발생자가 렌더링·UI·저장을 직접 호출하지 않는다.
- 보호 계약: 대시 Dodge와 피격 후 보호는 Hitbox 유래 피해만 막고 외부 전면 무적·Slash는 효과 피해도 막는다. 실제 HP가 감소한 효과 피해도 보호를 갱신한다. 이는 우리 원문 Case4를 따른 해석이며 효과 피해에 새 보호를 주지 않는 Sephiria와 구분한다.
- 시간·정리: Player가 scaled 게임 시각의 만료 기한을 소유한다. Rendering은 같은 경과를 읽어 별도 보호 타이머를 만들지 않는다. 사망·Player 비활성화·재배치는 보호 종료를 알리고, Rendering만 비활성화하면 원본색을 복원하며 논리 보호는 계속한다.

# 선택 사안 2
- 선택: 사용자 확정 — 피격 시 Player Sprite가 붉은색과 원본색을 번갈아 표시한다.
- 이유: 이유 미기록.
- 변경: 기존 원문의 투명색 깜빡임을 이번 빨강/원본색 요청으로 대체한다. 새 보호 진입에서 Sprite별 tint를 한 번 보관하고 원래 alpha는 유지하며 종료 시 복원한다. 효과 재피격은 새 경과로 표시를 다시 시작하되 깜빡이는 빨강을 원본으로 재저장하지 않는다.
- 수치: 보호0.75초·색 단계0.08초는 Inspector 초기 튜닝값이며 사용자 확정 밸런스가 아니다.
- 현재 기준: 실제 API·검사 결과·남은 아트/음향 범위는 GAME_SPEC 2.1.8을 따른다.
