# 선택 주제
주제 : ConsumeLine 명명과 F-P09~F-P11의 연속 구현
- 2026-11-15 사용자가 모호한 Try 접두사를 없애고 F-09부터 F-11까지 함께 진행하도록 요청했다. 현재 사양·구현·검증 원본은 [GAME_SPEC](../../GAME_SPEC.md)의 2.1.9~2.1.11이다.

# 선택 사안 1
- 선택 : 직접 작성한 API는 동작을 드러내는 이름을 쓰고 TryConsumeLine을 ConsumeLine으로 변경
- 이유 : 사용자가 Try 같은 모호한 접두사를 원하지 않음
- 제시된 다른 선택 사안들 : 별도 제안 없음
- 적용 : 실패 조건과 bool/out 반환 계약은 유지하고 호출부·검사·현재 Class/Sequence를 함께 변경한다. Unity·외부 API 이름과 과거 기록은 보존한다.

# 선택 사안 2
- 선택 : F-P09 사망·같은 Player 부활, F-P10 수정 상호작용, F-P11 각성·그로기·Slow를 함께 구현
- 이유 : 함께 처리하도록 요청한 이유는 미기록
- 제시된 다른 선택 사안들 : 별도 제안 없음
- 적용 : 기존 Q13·Q14·Q15·Q25 확정 사양을 기준으로 상태 발생자는 자기 상태와 사건만 발행하고 Spawner·UI·카메라·효과 구독자가 자기 책임을 처리한다. 사망은 DeathCount만 저장하고 체크포인트 HP는 덮어쓰지 않는다. 수정 완료가 HP·활성 이력·현재 위치를 저장하고 Spawner의 로컬 체크포인트를 갱신한다.
- 호환 : 과거 저장에 활성 수정 목록이 없으면 현재 CheckpointId부터 복원한다. HP0 저장은 최초 생성 게이트 안에서 회복하며 새 사망으로 세지 않는다.
- 구현 조정 : 사망0.8초·생성0.25초·수정0.2초·Slow2초/속도0.5배는 수정 가능한 초기 구현값이며 별도 밸런스 확정으로 간주하지 않는다. 흑백 재질·임시 안내/수정/문은 최종 아트 교체 위치를 제공한다.
