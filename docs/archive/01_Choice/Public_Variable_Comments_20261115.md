# 선택 주제
주제 : public 변수 옆에 역할·목적을 설명하는 한 줄 주석 작성
- 2026-11-15 사용자가 `public static GameManager Instance; // ...` 예시와 함께 기존 클래스의 public 변수 설명, 행동방침 및 작업 과정 반영을 요청함.

# 선택 사안 1
- 선택 : public 변수의 역할 또는 존재 목적을 선언 옆의 한국어 한 줄 주석으로 작성함. 이후 변수 추가·역할 변경 시 함께 갱신하고 코드 검토에서 누락·정확성을 확인함.
- 이유 : 변수의 역할·존재 목적을 한 줄로 정리해 달라는 요청. 별도의 선택 이유는 미기록.
- 제시된 다른 선택 사안들
  - 없음. 사용자가 직접 형식과 적용을 지정함.

# 반영 범위
- 현재 프로젝트에서 작성한 런타임·Editor 코드의 public 필드·static·상수·프로퍼티와 중첩 데이터 클래스에 적용함. 외부 패키지·레퍼런스 원본은 대상에서 제외함.
- 행동방침 원본은 [AGENTS](../../../AGENTS.md)의 Unity 코드 작업, 작성 양식·검토 순서는 [DESIGN 2.2](../../agents/DESIGN.md#22-주석-작성)에 둠.
- 실제 반영·검사 상태는 [STATUS](../../agents/STATUS.md)와 [PLANS](../../agents/PLANS.md)에 기록하며, 주석 추가를 새 게임 기능 구현으로 기록하지 않음.

# 선택 사안 2 — 짧은 어투와 코드 구역·연결 목적 설명
- 선택: 2026-11-15 후속 요청으로 한 문장 주석은 `로드 완료 대기`, `Title 복귀`처럼 마침표 없이 끝낸다. `~함.`은 두 문장 이상을 구분할 때만 사용한다.
- 이유: 기존 주석의 어투가 인공적으로 느껴진다는 사용자 의견.
- 선택: private 변수도 선언 옆에 목적을 적고, 함수에서 빈 줄로 구분한 각 구역의 맨 위에 역할·목적을 요약한다. 이벤트 구독·코루틴 실행과 의미가 불명확한 yield 대기는 코드 뒤 한 줄로 설명한다. yield break와 yield return null은 제외한다.
- 이유: 코드 구역의 역할과 구독·실행·대기 목적을 읽을 때 바로 알 수 있도록 하려는 요청. 반환 의미가 명확한 yield는 불필요한 설명에서 제외한다.
- 반영 범위: 현재 직접 작성한 런타임·Editor22개와 이후 작업 절차. 함수의 실행 코드·문자열은 바꾸지 않는다. 양식·검토 절차 원본은 DESIGN 2.2를 따른다.
