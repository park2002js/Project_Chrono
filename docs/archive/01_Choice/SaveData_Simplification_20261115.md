# 선택 주제
주제 : SaveData를 호출자가 key·타입을 아는 단순한 저장 구조로 변경
- 2026-11-15 사용자가 현재 SaveData가 지나치게 복잡하다고 판단하고, 세피리아 저장 시스템을 참고한 재작성을 요청함. 외부 입력부터 시작하는 현재 흐름의 시퀀스 다이어그램도 함께 요청함.

# 선택 사안 1
- 선택 : 요청자가 key와 데이터 타입을 알고 있다고 가정하고 직접 Get/Set을 사용함.
- 이유 : 현재 SaveData가 너무 고급지고 복잡하다는 사용자 판단. 호출자 정보가 충분하므로 추가적인 key·타입 검증 계층이 불필요함.
- 제시된 다른 선택 사안들
  - 기존 구현은 일곱 key·타입·값 범위와 고정 이진 순서를 강제했음. 별도 선택지로 제안된 것은 아니며 이번 요청으로 교체됨.

# 구현 해석과 원본
- 사용자 확정은 위의 단순화 방향임. `Field[]` XML, 현재 쓰는 `List<string>` 타입 등록, 기본값의 SaveManager 이동은 이를 충족하기 위한 구현 선택임.
- 세피리아 원본의 Dictionary 직접 접근·XML 직렬화를 참고했으며, 동적 타입명 복원·Steam Cloud·다중 백업 구조는 추가하지 않음. 실제 읽은 경로와 채택/생략 근거는 [GAME_SPEC 3.5](../../GAME_SPEC.md#35-레퍼런스-활용과-확인-한계)에 기록함.
- Q29의 파일 검사·백업 한 개·재시도·복구·종료 대기는 유지함. 파일 처리 규칙을 없애라는 요청으로 해석하지 않음.
- 현재 사양·구현과 외부 입력별 시퀀스는 [GAME_SPEC](../../GAME_SPEC.md)의 S05·S06 및 2.4에 두며 실제 확인 결과와 남은 작업도 그곳에서 갱신함.

# 선택 사안 2
- 선택 : 2026-11-15 후속 요청에 따라 SaveData.CommonPath를 사용자 문서 폴더의 `Project_Chrono`로 정하고 암복호화 기준 문자열을 `ProjectChrono`로 통일함.
- 이유 : 사용자는 복잡한 키보다 암호화 기능을 사용했다는 점을 중요하게 보며 세피리아의 SaveData·저장 관리자 구조 참고를 요청함. 문서 폴더 선택의 별도 이유는 미기록임.
- 제시된 다른 선택 사안들
  - 기존 AppData/persistentDataPath 아래 Saves 경로와 용도별 두 키 문구는 이번 요청으로 교체됨. 별도 선택지 제안은 없었음.
- 구현 해석 : 레퍼런스에 실제 존재하는 관리자는 `SaveManager`이며 `SaveDataManager.cs`는 없음. CommonPath 및 같은 문자열을 암복호화에 쓰는 방식을 채택하되 Saved Games/Sephiria 하위 경로는 복제하지 않음. 13자 ProjectChrono를 AES에 맞는32바이트로 변환하는 기존 SHA256 함수만 사용하고 Q29의 파일 검사·백업·재시도는 유지함.
- 문서 반영 : 사용자가 현재 클래스 역할의 Notion 1장 갱신과 구현된 케이스의 시퀀스 재작성을 직접 요청함. 자동 동기화나 향후 모든 외부 문서 수정 승인으로 확대하지 않음.
