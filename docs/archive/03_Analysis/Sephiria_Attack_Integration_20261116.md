# 대검 공격 이식 — 원작 계약과 R14의 연결

2026-11-16. 기능F-P03, 담당AttackController·PlayerCharacter·PlayerInputController와PlayerWeaponAnimationSetup·PlayerArtSetup. 이 문서는 실제로 읽은 원작 수치와 새3타의 추론을 구분한다. 최종 실행 결과는 GAME_SPEC2.1.3을 따른다.

## 2. 좌표·곡선·앞뒤

원작mainShoulderOffset=(.15625,.4375),Y축어깨Aim의위/아래오프셋은±.0625다. 북쪽어깨는(.15625,.5),SwingPoint는어깨에서+Y1이므로검기피벗은Player발밑에서(.15625,1.5)다. 원본검기는70×66·피벗(35,33)·16PPU를유지한다.

우리+X조준부모는어깨를(sign*.15625,위?.5:.375)에두고worldZ=atan2(y,x),localScale=(1,sign)으로반사한다. 클립위치는원작(x,y)를(y,-x)로바꾸고Z키/접선을보존한다. `R(aimX)*Sy(sign)*R(-90)=R(aimX-90)*Sx(sign)`이므로원작+Y기준과같다. 검Sprite의고정+90°/검기−90°정렬과원본피벗을포함한다.

1타는11/30초부터검앞,2타는.3초부터검뒤다. 원작Wait2/Wait3는각1/6초이며AS를적용하지않고끝자세에서다음준비자세로움직인다. Idle도원작호흡곡선을사용하고종료때Motion을0으로덮지않는다.

검기이미지는생성당시의회전/좌우/Player상대위치를보존하고Player의위치만추종한다. 원작SpriteFx.SetParent의followDelta와같은책임이다. 우리검기슬롯은Player직접자식으로재사용하며새조준부모의회전을따라돌지않는다.

## 3. 새3타 — 사용자 확정과 추론

- 확정모션: R14의1타1~24+2타16~45를직접연결한54표본. 마지막은원본2타종료경계라클립길이는53/60초이며추가유지프레임을넣지않는다.
- 확정검기: 보라23~25 V1/26~29 V2/30~32 V3/33~35 V4.파랑25~26 V1/27~29 V2/30~32 V3/33~35 V4.36부터둘다없다. 온전한두원본에서겹친픽셀만왼쪽파랑/오른쪽보라가앞이며비겹침을모두보존한다.
- **추론한입력정책:** 새3타는마지막검기가끝나는F36=35/60초/A부터클릭예약을허용한다. 준비/두베기/검기표시중의짧은클릭은버린다. 모션종료53/60초/A에서다음1타를시작할수있고추가쿨다운은0이다. 마지막검기뒤18/60초의회복이이미있다는근거다.
- **원작3타와차이:** 원작기본3타는AllowInputBuffer이벤트가없어짧은클릭을예약하지않는다. 이번값은사용자가추론을위임한새모션전용정책이다.
- 3타피해/전진은첫검기생성22/60초/A에한번만생성한다. 두번째색/되베기에서새DamageInstance나중복대상을만들지않는다. 기존강화배율1.5는유지하며이번요청으로재확정한밸런스값은아니다.
- 3타검기단계는확정모션시간에맞춰AS로진행한다. 원작1·2타는생성시점만AS를적용하고생성후.2초를보존한다.

## 4. 경계와 수명

첫1/30초안의짧은클릭은저장하지않는다. 허용후클릭은해제뒤에도한번남고,긴프레임이콤보유효창을넘겨도예약소비를우선한다. 버튼홀드는현재타종료후다음타를요청하며공격중매프레임새클릭을만들지않는다.

AS2에서는1타충돌이.18333초에생겨.33333초까지살지만2타는.3초에시작한다. 따라서각타의CollisionBox·피해·고정방향·수명·중복대상목록을독립재사용한다. 검기도동시수명을독립슬롯으로유지한다. 취소는모든판정/표시/입력예약/전진을정리한다.

비활성화때Animator가평가불가능하면공격일시정지speed0를즉시복구할수없으므로재활성OnEnable에서Idle·speed1을다시적용한다. 새전역객체를찾거나매프레임준비를반복하지않는다.

## 6. 후속 확정 — 입력 유무와 무관한 기본 전진 거리0.5

2026-11-16 사용자 확정으로1·2·3타 모두 이동 입력 유무와 관계없이 기본 전진 거리를0.5로 통일했다. `AttackDashSpeed=10f/3f`, `AttackDashDuration=0.3f`의 선형 감속을 구간 적분하므로 전체 거리는 `(10/3)×0.3/2=0.5`이며 실제 변위에는 기존 `SP/basicSP`를 곱한다. 무입력 배율 필드·거리 분기는 제거했다. 직전의 이동 입력0.6/무입력0.3은 더 이상 현행 사양이 아니다.

방향은 예약 클릭이나 타격 순간이 아니라 실제 각 타 시작의 MoveDirection을 보관하고, 그 값이0이면 해당 타의 AttackDirection을 사용한다. 타격 생성 시점에 그 방향으로 전진을 시작한다. 높은 AS에서 다음 타가 준비 중이어도 이전 전진의 속도/방향을 보존하도록 활성 전진 속도 캐시는 유지한다. Idle·이동·Wait의 검19,실제 공격19/21·검기21과 기존 모션/입력/판정 수명은 유지한다.

원작 `NewWeaponFireData.CalculateAttackDashDistance`는 같은 감속 면적을 계산하고 `CreateAttack_Before`는 타격 순간의 입력을 조회한다. 원작 초기속도4·시간0.3의 기본 거리는0.6이다. 이번0.5와 시작 시점 방향 고정은 사용자 맞춤 변경이며 원작 수치로 기록하지 않는다. 코드·생성기·Player 프리팹 반영 뒤 `project/Logs/PlayerAttackUnified-result.json`의 공격18묶음과 `PlayerAttackUnifiedDash-result.json`의 대시8묶음은 각각 success=true·error 빈값·배치 종료0이며 C# 오류0이다.1·2·3타의 입력/무입력0.5와 준비 중 입력 변경·AS2 전진 수명·검19/21·검기21을 재확인했다. `PlayerAttackUnified-verification.json`의 관련23파일/45자산은 원본/격리 일치·기준선 이후 변경0이며 동시 작업8개 런타임은 제외한다. Editor 검색 초기화 예외는 관찰됐고 게임 검사는 완료했으나 원본 직접 Play·제출 빌드·성능 측정은 미실행이다. 직전18묶음의0.3/0.6 결과는 새 거리의 검증 근거로 사용하지 않는다.
