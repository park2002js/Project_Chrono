# Class 구조

# Class들 목록

## Player Prefab 연관

- Character
    - 역할
        - BossCharacter와 PlayerCharacter의 부모가 되는 Monobehaviour Class이다.
        - 각종 Status와 기본 event, 함수들이 정의되어 있다.
            - 이곳에 몰아서 정의되어 있는 이유는, character로 쉽게 조회하기 위함 + 한 곳에 몰아서 정리하여 확인한 뒤, 모든게 확정되면 필요한 쪽으로 내려서 저장
    - 정의된 수치값들
        - Status 전용
            - HP, maxHP : 전자는 runtime에서 계속 수정되는 값, 후자는 초기화 할 때 사용하는 값
            - AD, basicAD : 전자는 runtime에서 매 공격시마다 조회되는 값이며 수정가능. 후자는 초기화 할 때 사용
            - AS, basicAS : 전자는 runtime에서 공격 animation 속도와 공격간의 텀을 결정해야 할 때마다 조회되는 값이며 수정가능. 후자는 초기화 할 때 사용
            - SP, basicSP : 전자는 runtime에서 이동할 때마다 조회되는 값이며 수정가능하다. 후자는 초기화 할 때 사용
        - 특정 클래스와 관련된 시스템 수치 값 (이후 모든 적정값이 결정되면, 해당 수치가 쓰이는 class로 옮길 예정)
            - lineLength : Draw시 그려지는 Line의 길이를 정의한다. (Player 전용)
            - dashLength : dash 사용 시의 벡터 방향 이동 거리를 정의한다. (Player 전용)
            - dashDodgeTime : dash 사용 시, 피격 무시 상태가 얼마나 지속되게 할 것인지 정의한다. (Player 전용)
            - dashNoInputTime : dash 사용 시, 다른 입력이 무시되는 시간을 얼마나 지속되게 할 것인지 정의한다. (Player 전용)
            - dashCoolTime : dash 사용 후, 다시 Dash 입력이 들어올 경우 이를 무시하는 시간을 정의한다. (player 전용)
            - attackNoInputTime : Attack 중에 Move를 제외한 다른 입력이 무시되도록 하는 것을 정의한다. (player 전용)
            - attackCoolTime : attackNoInputTime이 끝난 뒤에 다시 Attack 입력이 들어올 경우, 이를 무시하는 시간을 정의한다. 공격 속도로 감소될 수 있다. (player 전용)
            - attackComboTime : attackComboTime이 끝나기 전에 입력이 들어오면 현재 attackComboCount를 1 증가시키고, Timer를 갱신시킨다. (Player 전용)
            - attackSP : attack 상태인 동안 move 이동 명령이 내려왔을 때, 어떤 이동속도로 이동하게 만들지를 정의한다. (Player 전용)
            - drawNormalCoolTime : Slash 이후, Draw에 걸리는 쿨타임 (Player 전용)
            - drawCancleCoolTime : Draw 상태에서 취소했을 때와, Draw 확정 이후 상태에서, 다시 Draw를 할 수 있기까지의 쿨타임 (Player 전용)
            - slashAfterDrawCoolTime : Draw가 확정된 직후에 바로 slash를 쓰지 못하게 하기 위한 목적으로써 부여되는 짧은 시간 (Player 전용)
            - lineLifeTime : Draw가 확정되어 저장된 Line이 유지되는 시간을 정의한다  (Player 전용)
        - attackComboCount : 현재 공격 콤보가 몇번째인지 저장한다. 0일 때 일반 공격시 첫번째 모션이, 1일 때 공격을 하면 두번째, 2일 때 공격을 하면 마지막 모션이 나가고 다시 0으로 초기화 된다. (Player 전용)
        - groggyStagger : 현재 그로기 수치를 저장하고 관리한다. 100이 되면 보스를 Groggy 상태로 만든다. (Player 전용)
    - 정의된 상태
        - IsDead : 사망 상태를 알린다.
        - IsDodge : 회피 상태를 알린다. 이때에는 Hitbox를 통한 피격에 대해 무시 상태가 되지만, 어떤 특정한 효과가 존재함으로 인해 체력이 닳는 것은 적용된다.
        - IsInvulnerable : 무적 상태를 알린다. 이때에는 어떠한 데미지도 입지 않는다.
        - IsDash : 회피 모션 상태를 알린다. 이때는 키입력이 불가하다. (Player 전용)
        - IsAttack : 공격 상태를 알린다. (Player의 경우) 이때는 키입력이 Move로 인한 느린 이동외에는 불가하며, 마우스 커서 위치에 따른 sprite 방향 변경이 일어나지 않는다.
        - IsAttackCombo : 공격 콤보가 유지중임을 알린다. 이것이 켜져있을 때 공격이 들어가면 다음 공격 콤보 모션이 나간다. (Player 전용)
        - IsCutScene : 컷신 진행 중인 상태를 알린다. 이때는 정해진 animation이 출력되며, 키입력이 불가하고, UI가 사전에 정의된 방식대로 제거된다.
        - IsFever : 각성 상태를 알린다. 이때에는 각종 수치가 증가하고 오라 같은 FX가 발생한다 (Player 전용)
    - 정의된 공통 함수들
        - ApplyDamge : Character가 데미지를 받을 수 있는 상황인지 내부에서 확인 후, 데미지를 적용하는 부분이다.
        - ApplyBuff : Character가 사전에 정의된 버프를 전달받는다.
        - RemoveBuff : Character가 사전에 정의된 버프를 해제하라는 신호를 전달한다.
    - 정의된 이벤트
        - OnDie : 죽을 때 발생
        - OnRevive : 죽음 이후 다시 생성될 때 발생 (Player 전용)
        - OnDamaged : 피해를 입을 때 발생
        - OnCutScene : 컷씬이 재생될 때 발생
    - 연관된 것들
        - [자식] PlayerCharacter : Player 전용 Character 클래스이다.
        - [자식] BossCharacter : 각 Boss들의 부모역할을 하는 Boss 전용 Character 클래스이다.
- PlayerInputController (`Mono`)
    - 생성
        - 게임 내에 들어왔을 때부터 필요함.
        - 단 하나의 InputController가 Spawn된 단 하나의 Player와 연결되어야 함
        - 생성된 이후로는 Scene 전환시에도 제거되지 않음
    - 역할
        - Player로 입력을 전달하는 System쪽 코드로, 자신에게 존재하는 “입력”과 “입력 가능”을 확인한다. 저 “입력 가능” 여부를 나타내는 bool 변수의 상태는 player 측에서 자신의 상태에 맞게 관리한다.
            - 이는 PlayerInputController와 PlayerCharacter 간의 역할을 구분하기 위함이다.
            - PlayerInputController는 “사용자가 원하는 입력 정보를 전달”하는 책임에 집중하며,
            PlayerCharacter 쪽에서는 해당 정보를 바탕으로 “캐릭터의 이번 프레임 행동을 계산하고 확정”하는 책임으로 나눈 것이다.
            - 여기에서 발생한 2개의 update는 그러한 선택의 구현 방법 중 하나이다.
        - PlayerCharacter에서 제공하는 API에 맞춰 입력에 따라 필요 함수를 호출한다.
        - 계속해서 **키다운**을 하고 있으면 해당 입력이 계속해서 들어오는 것으로 처리한다.
        - Unity의 InputSystem에서 사용할 함수를 제공한다.
        - Player가 아닌 ‘외부의 상황’(CutScene 재생, 로딩 등)이 ‘**BlockInput**’ 변수를 수정한다. Player는 PlayerInputController를 알지 못하기 때문이다.
        - Player측의 각각의 상황에 따른 입력 수정은 Player의 내부에서 담당한다.
        - BlockInput 변수는 ‘컷씬’ 상태나 ‘로딩’상태일 때 외부에서 bool 변수 값을 조정한다.
        - Player의 Draw 상태를 인지하여, InputSystem이 Draw에 맞는 입력을 하도록 만든다.
    - ***키다운*** 대상
        - 플레이어의 일반 공격 : 계속 누르면 공격이 가능한 타이밍에 바로 눌린것으로 판정된다.
        - 특정 방향 이동
    - 보유 함수
        - Awake() : PlayerCharacter와 연결
        - Update() : 매 프레임마다 키보드 입력을 연결된 함수에 전달 + 화면에 찍힌 커서를 투영하여 위치를 갱신(`카메라.ScreenToWorldPoint(aimInput)`)
    - 연관된 것들

- PlayerCharacter
    - 생성
        - StageManager에 의해 준비된 Prefab이 복제되어 생성된다.
        - 초기화는 Component의 PlayerSpawner에 의해 일어난다.
    - 역할
        - Player를 나타내는 최상위 Class
        - 이 Class 객체는 1인 게임에 맞게 1개 뿐이며, 나머지 기능은 이 객체가 소유하고 호출하는 것으로 연결된다.
        - 상태가 변경될 때, PlayerInputController의 bool BlockInput의 수명을 다룬다.
    - Prefab 구성
        - [Root] Player (gameobject, 여기에 Component로 대부분의 코드가 붙음)
    - 소유하는 Script Component(기능)
        - SkillController : 플레이어가 쓰는 Draw & Slash 스킬에 대해 관리
        - WeaponController : 플레이어의 무기 렌더링과 애니메이션, 기본 공격 및 연속 공격 콤보에 대해 다룸
        - CharacterBody : 플레이어의 이동, 대쉬, 피격 등을 다룸
        - CharacterRendering : 플레이어의 몸체와 애니메이션을 연결한다.
        - PlayerSpawner : PlayerCharacter가 사용되거나 서로 상호작용이 필요한 것들끼리 연결시키는 초기화 및, PlayerCharacter의 status 수치들을 정해진 기본값으로 초기화함
    - 연관된 것들
        - [Script] Character : 부모 클래스로, Status와 각종 이벤트 등의 기본 틀이 정의되어 있음
- PlayerSpawner (`Mono`)
    - 생성
        - player object의 component로 붙어있음
        - playerCharacter가 Awake로 해당 Spawner 객체를 가져온다.
    - 역할
        - Player의 동작과 피드백 및, 특정 상황에 대해서 이를 알리거나 연결을 끊어야 하는 것들을 담당한다.
        - Player의 구성 및 초기화를 담당한다.
        - Player가 체크포인트에서 생성되어야 할 때, Player의 Prefab의 복제본 Instance를 지정된 좌표에 생성하고 초기화한다.
        - Player가 체크포인트에서 재생성되어야 할 때, Player의 Prefab을 특정 위치로 옮기고 다시 초기화한다.
        - Player의 사망 시, Boss의 초기화를 담당
    - ***고찰할 부분***
        - Player가 사망했을 때, 재생성이 아니라 아예 destroy 시켜버리고 다시 생성시킬 때, 두 버전의 로딩 속도 차이? 이런걸 비교해볼만 할 듯
    - 보유함수
        - playerSpawn() : 지정된 특정 위치에 생성
        - playerInit() : 플레이어의 각 수치를 초기화하하여 기본 상태로 설정함
    - 연관된 것들
        - [object] Player Prefab instance : 생성된 Player 인스턴스와 연결되어 초기화가 가능
        - [object] CheckPoint 배열 : 마지막으로
        - [script] GameManager(일단) : 신호를 전달 받거나 Checkpoint 위치 알기 위함?
        - [script] SaveManager : SaveData로부터 마지막 세이브 위치를 조회함. 수정에서 재생성이면 그에 대한 모션을 보이기 위함
- AttackController (Mono)
    - 생성
        - player object의 component로 붙어있음
        - playerCharacter와 playerSpawner가 Awake시 해당 객체를 가져온다.
    - 역할
        - 플레이어 커서 위치를 추적하여 무기 Sprite의 Transform 갱신
        - 공격 시의 커서 위치에 기반하여, 무기 animation 실행 명령과 공격 Collision 생성 및 검사를 진행한다.
        - 플레이어의 공격 animation과 FX animation과, 그것의 방향, 공격 Collision 생성 및 적에게 Damage 입히기를 담당한다.
        - 공격 콤보의 유지 여부 확인, 관리 및 초기화를 담당한다.
    - 보유함수
    - 연관된 것들
- SkillController (Mono)
    - 생성
        - player object의 component로 붙어있음
        - playerCharacter와 playerSpawner가 Awake시 해당 객체를 가져옴
    - 역할
        - 플레이어의 Draw와 Slash 공격의 로직을 담당
        - Draw시, 연출과 함께 Draw 입력 상태로 만들고 Line을 그릴 수 잇는 환경을 만들어야 함
        - Draw과정에서 확정된 ‘startPoint’와 ‘endPoint’에 기반해서 Line을 정의한다.
        - Slash시, 연출과 함께 Line쪽에 ‘특수 공격’을 날리도록 한다.
    - 연관된 것들
        - [Script] LineDrawer : Draw 상태에서 Line을 그리는 쪽의 로직을 담당한다.
        - [Script] LineSlasher : Slash 상태에서 정의된 Line에 기반해 Slash 효과 및 로직을 담당한다.
        - [struct] Line : Slash 할 Line에 대한 정보가 담긴 객체를 정의하기 위한 구조체. 시작점과
- LineDrawer
    - 생성
        - SkillController가 Awake 과정에서 생성
    - 역할
        - Draw 상태로 전환되는 연출과, Draw 상태가 해제되는 연출, 그리고 그 과정에서 변화하는 상태 전이를 정의한다.
        - Draw 상태에서의 유지될 플레이어 화면을 정의하고, 그것이 되도록 UI측 및 연관된 것들에게 알린다.
        - Draw 상태에서는 찍히는 startPoint와 endPoint의 좌표를 임시로 저장하고, Draw 확정시 이를 SkillController 측으로 넘긴다.
        - Draw 상태에서, startPoint가 찍혔을 때 Line 연출과, endPoint가 찍혔을 때 Line 고정, 재정의 키를 눌렀을 때 사라지게 하는 것까지 정의한다.
        - Line이 확정된 순간으로부터의 수명과, Slash 되지않고 Map에 존재하는 동안의 연출을 관리한다.
            - 수명이 짧아짊을 VFX로 표현한다.
            - Line이 Slash로 인한 것이 아닌, 수명이 다 되어 자연적으로 사라지는 경우 이에 대한 연출을 관리한다.
        - 만약 Line이 있는 상태에서 다시 Draw를 한다면, Draw 상태에서는 ‘임시’로 좌표를 저장할 뿐이므로
- LineSlasher
    - 생성
        - SkillController가 Awake 과정에서 생성
    - 역할
        - Slash 스킬 뿐만 아니라, 생성된 Line에 대해서 연출 및 효과를 관리한다.
        - Line에 대한 정보와 함께 Slash 명령이 들어오면, 해당 정보에만 기반하여 로직을 실행한다.
        - Slash 상태로 전환될 때, 그때의 연출부터 해제되기까지의 UI 및 카메라 이동, animatino 출력까지의 연출을 정의한다.
        - Slash 명령을 받으면, Line에 정의된 크기대로 ‘Collision’을 생성하여 겹치는 대상들을 구별해낸다.
            - 투사체라면 player의 그로기 게이지를 정해진 수치값대로 채우고,
            특수 투사체라면 그로기 게이지 뿐만아니라 Player에게 각성 버프를 발동시키며,
            그 외의 적 대상은 player의 공격력에 기반하여 데미지를 입힌다.
- PlayerBodyController
    - 생성
        - Player object의 component로 붙어 있다.
    - 역할
        - [피격] 초기화 과정에서 전달받은 인자에 기반해, 몸체 hitbox를 생성하고 피격 판정을 검사한 뒤, 피격이 확정되면 Player에게 Damage를 입힌다. 피격시 피격 무시 상태에 들어가는 시간을 조절하며, 또한 피격시의 VFX 효과도 관리한다.
        - [이동] Player의 8방향 이동에 대해서, player 측의 speed 수치에 기반해 실제로 몸체의 월드좌표를 수정시키며 이에 맞춰 각각의 Sprite의 animation 재생을 한다. 이동속도 배율이 걸리면 이에 맞춰 animation 재생 속도도 변화시킨다.

# Sequence D

플레이어 input : 주황색

내부 로직 : 초록색

내부 변수 : 빨간색

변경 가능성 : 형광펜

## |글로 정리한, 플레이어 Input에 따른 발생 가능 행동들

### 1. player 이동

- 특정 방향의 방향키를 키 다운함
    - → **playerInputController**측에서 행동가능여부를 확인한 뒤,  
    눌린 방향키가 담당하는 각각의 방향들에 대해서, 모든 눌린 이동 키들의 방향 벡터 합을 구한 뒤, 이것을 Player측에 전달함 변수로 전달함
    - → Player 측은 내부의 Update에서 해당 변수 값을 조회하여 가져온다.  이는 Input측의 우선도가 Player보다 높기 때문에 가능한 일이다.
    - → 그 방향 벡터에 이동 속도를 곱해 **이동 벡터**를 구함 (이동속도를 외부에서 직접 player측의 하나의 speed 값을 수정하게 해서, 조회하는 측에서는 bool로 현재 상태를 구별할 필요 없이 만들거나, 혹은 그냥 쉽게 매 움직임마다 bool로 구분하는 것 두가지 중 어느것이 더 성능이 좋을지 비교)
    - → 해당 벡터에 따라 player의 좌표를 수정한다.

### 2. Player의 바라보는 방향

- 마우스의 커서가 특정 위치에 존재함
    - → PlayerInputController측에서 행동가능여부를 확인한 뒤(즉, 컷씬이나 로딩씬이 아닌지 확인), 현재 마우스 커서의 위치를 카메라로부터 가져와 좌표를 구함
    - → 구한 좌표를 Player 측으로 매프레임 전달하여 저장함
    - → Player측은 필요한 곳에서 내부의 update에서 매프레임마다 해당 좌표를 위치를 조회함
    - → Player Object의 중심 좌표와 해당 좌표와의 관계를 기반으로 “**방향 벡터**”를 구함
    - → 해당 **방향 벡터**를 기반으로 Sprite의 8방향 중 하나를 렌더링하고 이에 맞춰 animation을 조정한다.

### 3. 대시 (회피)

- Dash에 해당되는 키를 누른다
    - → playerInputController측에서 행동가능여부를 확인한 뒤, Player의 dash 함수를 호출
    - → 호출된 Player 측에서는 dash가 가능한지 판단하고, 가능하다면 현재의 이동 방향을 조회함
        - if : 현재 이동 벡터의 크기가 0이라면 → **방향 벡터(커서)**의 방향에 맞춰 정해진 길이만큼 Dash
        - if : 현재 이동 벡터의 크기가 0 초과라면 → **이동 벡터(키보드)**의 방향에 맞춰 정해진 길이만큼 Dash
- Dash를 시작했을 경우
    - → OnDash 이벤트 발생
    - → Dash animation & fx 시작 + 피격 무시 상태 타이머 시작 + Dodge 상태 타이머 시작 + 다음 Dash 가능 CoolTime 타이머 시작
- 피격 무시 상태에서 Player의 hitbox에 적의 공격이 닿으면
    - → Player이 ApplyDamage를 호출
    - → applydamage측에서 피격 무시 상태인지 여부를 검사
    - → Dodge 상태이므로 피해 적용 불가를 반환

### 4. 일반 공격시

- 플레이어가 일반 공격키를 누름
    - → playerInputController측에서 행동가능여부를 확인한 뒤, Player의 Attack 함수를 호출
    - → 호출된 Player 측에서는 현재 일반 공격이 가능한지 판단한다(공격 속도에 기반하여, 다음 공격 가능 시간이 만족되었는가?, 다른 입력 불가 상황이 존재하지 않는가?)
    - → 일반 공격이 가능하다면, 지금이 몇 번째 콤보인지 조회한다.
        - if : 카운트가 0이라면 → 첫 기본 공격 모션을 시작 + 콤보 카운터 1 증가 + 콤보 Timer를 등록한다.
        - if : 카운트가 1이라면 → 두번째 기본 공격 모션을 시작 + 콤보 카운터 1 증가 + 콤보 Timer 갱신
        - if : 카운트가 2라면 → 세번째 기본 공격 모션을 시작 + 콤보 카운터 및 Timer 초기화
- 콤보 Timer 등록시
    - → 콤보 Timer는 내부적으로 관리되며, Player측에 정의된 콤보 시간을 따른다.
    - → 시간이 다 지나기 전에 갱신되면, 기존값으로 되돌린다.
    - Timer가 다 되면 스스로 제거되며 Counter를 0으로 초기화한다.
- N번째 콤보 공격 실행 명령시
    - → 공격 상태가 되어 Move 입력을 제외한 나머지 입력을 차단 + 공격키가 눌린 시점에서의 마우스 커서 위치를 조회
    - → 공격 animation 실행
    - → animation의 특정 프레임에서 피격 판정 여부 체크를 위한 CollisionBox 생성
    - → 정의된 프레임 동안 Collisionbox가 BoxCast를 해서 RayCastHit 2D 배열을 얻어냄
    - → 그 배열에서 Hitbox를 조회하여 맞은 이들을 구분해내며, 이 과정에서 한번의 공격에 중복 적중이 되지 않도록 조정한다.
    - → Hitbox에 맞은 대상들에게 데미지를 DamageInstance에 공격자 정보를 담아서 전달한다.
    - → 공격자가 유효 공격자라면, ApplyDamage 처리를 한다.

### 5. Draw 시

- 플레이어가 Draw 스킬 키를 누름
    - → playerInputController측에서 행동가능여부를 확인한 뒤, Player의 Draw 함수를 호출
    - → 호출된 Player 측에서는 현재 Draw 스킬키를 누르면, 사용 가능한 상태인지 확인한다 (쿨타임이 돈 상태인지, 사용 가능한 상태인지 확인)
    - → 사용 가능하면 player의 draw 스킬을 사용한다.
- 플레이어의 draw 스킬 사용시
    - → draw 상태가 된다.
        - [로직] draw 상태에 저장되고 있었던 point들과 line들이 모두 초기화된다. (Line이 확정된 상태에서도 이를 Slash에 쓰지 않고 Draw 상태가 되더라도, 그 때의 상태에서 Line 확정을 하지 않고 다시 되돌아오면, SkillManager에 저장된 Line이 갱신되지 않으므로 그대로 유지된다.)
        - [UI] 플레이어를 제외하고 화면이 약간 어두워지며, UI가 밖으로 Fade out 된다. (이는 컷씬 시의 UI 이동과 동일하다)
        - [카메라] 플레이어를 중심으로 카메라가 줌 아웃된다.
        - [object] 플레이어와 투사체 및 Boss의 움직임 등이 모두 멈춘다.
        - [input] player의 input이 draw 전용으로 바뀐다.
- 플레이어의 **draw 상태 해제**시
    - draw 상태가 되면서 변경되었던 [UI], [카메라], [object], [input]이 Idle 상태의 것으로 변경된다.
- draw 상태에서 점 확정 키를 누를 시 (기본 : 마우스 좌클릭)
    - if : 점이 없다면 → 클릭 좌표를 ‘startPoint’로 저장한다. → 점이 확정 순간, 해당 점을 시작점으로 하고, 해당 점에 대한 커서의 위치를 방향으로 하는, 정해진 길이의 Line을 계속 렌더링한다.
    - if : 점이 1개 존재한다면 → 점을 찍은 좌표를 ‘endPoint’로 저장하고 선이 고정된다. 이때 endPoint는 방향의 역할로, endpoint가 선의 길이보다 짧거나 더 길게 찍혀도 선의 길이는 동일하게 유지된다. → **점 2개가 존재**하므로 Draw 확정 키가 활성화 된다.
    - if : 점이 2개 존재한다면 → 점 확정 키가 눌려도 점 상호작용이 발생하지 않는다.
- Draw 상태에서, Draw 상태 해제 키를 누른 경우 (기본 : draw 스킬키와 동일한 키)
    - → 저장한 점과 선이 모두 초기화됨 → **Draw 상태가 해제**됨 → 짧은 재사용 대기시간이 부여됨
- Draw 상태에서, 점 초기화 키를 누른 경우 (기본 : R키)
    - → draw 상태에서 확정된 점들의 좌표가 모두 사라지며, Line이 제거된다. draw 상태는 유지된다.
- Draw 상태에서, 활성화된 Draw 확정 키를 누른 경우(기본 : F)
    - → 그려진 Line의 시작과 끝 좌표가 skillManager에 저장됨
    - → Draw 상태가 해제됨
    - → 필드에 그려 놓은 Line이 특정 Fx로 나타남
    - → Draw 스킬의 재사용 대기시간이 걸린다.
- SkillManager에 Line이 저장될 경우
    - → LineDrawer에서 Line의 생명 타이머를 발동하기 시작한다.
    - → Line의 생명 타이머가 점점 짧아질 수록, 특정 시간 지점부터 점점 깜빡거림 주기가 빨라지는 Fx animation이 시작된다.
        - if : Line이 slash 되지 않고 생명이 다한 경우 → 전용 fx 연출이 발동됨 + Destroy되어 사라진다는것을 알림

### 6. Slash 시

- 플레이어가 Slash 스킬 키를 누름
    - → playerInputController측에서 행동가능여부를 확인한 뒤, Player의 Slash 함수를 호출
    - → 호출된 Player 측에서는 현재 Slash 스킬키를 누르면, 사용 가능한 상태인지 확인한다 (쿨타임이 돈 상태인지, Line이 존재하는지, 사용 가능한 상태인지 확인)
    - → 사용 가능하면 player의 slash 스킬을 사용한다.
- Slash 스킬 사용시
    - → Slash 연출이 발생한다
        - 첫 단계
            - 컷씬 상태로 정의하여, 무적 상태가 되도록 한다.
            - [카메라] 현재 플레이 중인 플레이어가 보는 화면을 가까이서 보듯, 플레이어 캐릭터를 중심으로 카메라가 zoomin된다.
            - [ui] 플레이어를 제외하고 화면이 어두워지며, 카메라 연출에 따라 UI도 zoomin에 맞춰 자연스럽게 화면 밖으로 빠져나가게 된다.
            - [object] Boss와 투사체, 그리고 player의 움직임이 멈춘다.
            - [animation] 플레이어의 slash animation이 재생된다.  해당 animation은 Slash가 실제로 효과가 발동된 이후에도 지속될 정도로 길지만, 이는 player가 slash 적용 이후 이동할 때의 animation이나 다른 특정 행동으로 뒤집어 씌워질 수 있다.
        - 두번째 단계
            - 전용 animation의 특정 프레임 지점에서, UI, 카메라 줌이 원상태로 돌아오고, 그와 동시에 Line이 있던 곳에 마치 공간참이 일어난 것처럼, 해당 경로에 연출이 발생한다. (이에 대해 추후 자세히 정의하더라도 별도로 설정할 수 있도록 미리 준비해 놓는다)
    - → 정의된 연출 시간이 끝나기 직전 마지막 정지된 시점에서의 1프레임 동안 Line이 위치한 곳에 일정 너비와 길이의 CollisionBox를 만들어 Raycast 검사를 해, 그것에 맞은 이들의 HitBox를 통해서 대상들의 정보를 가져옴
        - if : 투사체일 경우 → 그것을 파괴하고, player의 그로기 게이지를 채운다.
        - if : 특수 투사체일 경우 → 해당 투사체가 보스를 향해 반사되고, 플레이어가 각성 상태가 된다.
        - if : 보스일 경우 → 단순히 보스쪽에 ‘특수 공격’으로 데미지를 입혔다는 DamageInstance 정보와 함께 피해를 전달한다. → 이때, 보스쪽에서 해당 특수 공격으로 특정 조건이 만족되면 그로기 상태에 빠지게 된다.
    - → Line과 점에 대한 정보가 초기화 된다.
    - → draw가 재사용 대기시간에 걸리며, Line이 사라져 Slash 스킬이 비활성화 된다.
    - → 이동 가능한 상태가 된다.

## |게임 시작부터 main에 들어오기 까지

### 1. 게임 타이틀

- 게임을 시작 → title animation 출력 →  UI 및 Manager 설정됨 → SaveManager를 통해 Local 파일에서 세이브 데이터를 로드 시도함 → 모든 준비가 완료되면 Title 화면에 진입
- “**게임 시작 버튼**”을 누름 → 세이브 데이터에 기반해 진행도를 계산하여 전용 UI에 띄움
- 세이브 데이터 “**슬롯**”을 누름
    - if : 빈 파일일 때 → 첫 Tutorial 화면으로 넘어간다. (형식 상 맵의 시작에 활성화된 체크포인트를 두고, 그곳에서 컷씬과 함께 시작함)
    - if : 진행중인 파일일 때 → 마지막 진행상황에 기반에 게임 시스템을 **초기화**하고, 마지막 **체크포인트**에서 **생성**
    - if : 100% 완료된 파일일 때 → 초기화 후 재시작을 물어본다.

### 2. 게임 시스템 초기화

1. GameManager가 Title 씬에서 MainWorld 씬으로 넘어온다. (로딩창 시작)
2. SaveManager가 지정된 위치로부터 마지막으로 저장된 시점의 데이터를 가져와 현재의 기록을 복원한다.
3. StageManager가 맵 생성, 보스 prefab들 복사 후 생성 및 배치, 플레이어 prefab 객체 복사 후 생성을 한다.
    - MapGenerator는 하나의 큰 Map을 생성함
        - 맵 생성은, 1안, 2안, 3안이 있으며, 현재는 1안으로, 하나의 MainWorld 씬에 모든 Map을 생성하고 모든 보스들을 배치하여, 그 안에서 player가 활동하게 하는 것이다.
    - BossGenerator는 Boss들을 배치한다.
        - 이때, SaveManager의 진행도에 기반하여, 보스 배치시 죽은 sprite만 배치하게 할 것인지 (아니면 아예 배치하지 않거나), 아니면 실제로 prefab을 복사하여 배치할지 결정한다.
        - 보스들과 플레이어의 이후 동작은 그 내부에서 정의된 초기화 과정을 따르도록 한다. (보스는 생성시 지정된 위치에 전투 Trigger를 생성)
    - Player 생성만 StageManager가 담당하고, 이후 배치는 PlayerCharacter 내의 playerSpawner가 담당한다.
4. PlayerCharacter는 자신의 Component인 PlayerSpawner 객체를 가져온다.
5. PlayerSpawner 객체는 플레이어에게 필요한 기능들과 이벤트에 연결시킨다.
    - 연결 목록
        - UI들
        - PlayerCharacter의 이벤트들 (OnDie, OnRevive, OnDamaged)
6. PlayerSpawner는 SaveManager로부터 마지막 체크포인트 시점의 HP 상황을 조회하여 현재 HP 상황에 반영한다. 그리고 나머지 수치값들은 PlayerCharacter에 저장된 기본 값을 따른다.
7. Player 배치 및 초기화, Boss 배치 및 초기화, Map 현재 진행도 반영, UI 준비가 모두 완료되면, 로딩창을 닫고 Player가 체크포인트에서 cutscene을 보여주는 것으로 이어진다.

### 3. Save 갱신

1. SaveData 로드
    - 게임 시작시 GameManager는 SaveManager에게 세이브 데이터를 로드하라는 명령을 내림
    - SaveManager는 세개의 세이브 슬롯에 들어갈 3개의 세이브 파일 이름에 대해서, SaveData 객체에 정의된 대로 세이브 데이터를 불러오는 것을 시도
    - SaveData는 내부에 정의된 대로 Local에서 전달한 파일명을 검색한 뒤, 정의된 키로 복호화한다.
    - 복호화된 데이터를 보유한 SaveData 객체를 SaveManager가 보유함으로써 Load가 완료됨
    - SaveData 객체에 정의된 Get함수를 통해 게임 초기화 과정에서 필요한 값을 불러와 설정한다.
2. SaveData 갱신
    - SaveData 갱신을 원하는 측에서는, 전역으로 정의된 SaveManager를 통해 현재 SaveData를 조회할 수 있다.
    - SaveData 객체에 정의된 Set 함수를 통해 SaveData 내의 저장된 Dictionary 값을 갱신한다.
    - 갱신 이후 명시적으로 SaveManager의 Save 함수를 호출하여 비동기로 세이브 파일이 저장되도록 만든다.

## |Player가 시스템과 상호작용하며 생길 수 있는 일

### 1. Player 생성

- 공통 : Player 생성 명령시
    - → 마지막 체크포인트 수정 옆에서 앉았다가 일어서는 animation을 출력 + animation 출력이 끝날 때까지 CutScene 상태로 인해 Input이 무시됨
    - → 체크포인트의 활성화 여부에 따라 열림 여부가 결정되는 “보스 입장 문”은 체크포인트를 활성화하여 저장된 이후이기 때문에 항상 열려있음
- 마지막 진행도 시점에 따른 케이스
    - if : 보스를 클리어 했으나 그 다음 체크포인트를 활성화 하지 않은 경우 
    → 마지막 체크포인트 장소에서 Player 생성이 되며, 
    보스는 죽은 상태로 배치한다. (이는, 보스 클리어 이후 세이브 갱신이 일어나기 때문에, 게임 로딩과정에서 보스 배치시에 이것이 반영된 결과이다.)
    - if : 체크포인트 갱신 이후 만나는 보스를 쓰러뜨리지 못한 경우 
    → 마지막 체크포인트 장소에서 Player 생성이 된다. → SaveManager에게 보스 조우 정보를 조회한 뒤, 첫만남인지 아닌지에 따라 연출 여부가 결정된다.

### 2. Player 사망

- Player에서 ApplyDamage()로 인해 체력이 감소하였는데, 0이 되었을 경우
    - → OnDie() 이벤트 발생
    - → Boss와 OnDie 이벤트 구독을 서로 해제함 + saveManager를 통해 death counter 1 증가시키고 비동기로 저장함
    - → 컷씬 상태가 됨 + UI들이 화면 밖으로 이동하는 연출 + 화면이 어두워짐 + player의 사망전용 animation과 FX가 발동 + 카메라가 플레이어 중심으로 이동함
    - → 모든 연출이 끝나면 검은색 화면으로 바꿈 + 비동기로 Boss 초기화 및 재배치 작업을 시작함
    - → 재배치가 완료되면 ‘생성’의 로직을 따르도록 넘김 (검은색 화면에서 다시 UI 배치가 완료되어 있는 상태의 player 화면으로 되돌림 + 수정 앞 정해진 위치에서 player 생성 animation 출력 + 수치값 초기화)

### 3. 수정 체크포인트와 상호작용

- **“비활성화**된 **수정 체크포인트”**는 Trigger 역할의 Collision을 보유함
    - → 해당 Collision에 Player가 들어오면, 수정 체크포인트는 PlayerInput에게 ‘**상호작용 상태**’를 **활성화**하고 **본인 객체**를 전달한다.
    → Player의 UI측에서 상호작용키인 [F] 이미지를 플레이어 캐릭터 머리 위에 띄운다. + 상호작용 키 입력이 다른 입력키들보다 더 우선 확인되어서, 같은 키가 매핑되더라도 먼저 인식되어서 상호작용하게 된다.
    - → Collision안에 들어온 player가 다시 밖으로 나가면, 수정 체크포인트는 PlayerInput에게 ‘**상호작용 상태**’를 **비활성화** 한다.
    → 수정 체크포인트에 ‘activateCheckPoint’ 함수가 호출된다.
- 플레이어가 **상호작용 상태**가 **활성화**되어 있을 때, 상호작용 키를 눌렀을 경우
    - → Player가 **컷씬 상태**가 됨 + Player가 상호작용 전용 animation을 **비동기**로 재생시작 + 수정 체크포인트의 **activateCheckPoint 함수**를 호출
    + activateCheckPoint 함수가 호출된 수정 체크포인트는, SaveManager에게 체크포인트 갱신을 알림 + 체크포인트 활성화 animation이 비동기로 재생됨 + ‘활성화’ 상태가 되어서 Collision이 사라짐, 이것들이 동시에 일어남
    - → 플레이어의 상호작용 전용 animation이 끝나면 **일반 상태**가 되어, 더이상의 상호작용이 되지 않도록 Trigger를 제거하고, 해당 내용을 save 파일에 비동기로 저장하도록 명령한다.
    - (만약, 비동기 로딩을 하기로 결정했다면) → 다음 보스의 초기화가 완전히 완료되었는지 체크하고, 다다음 보스가 준비하도록 비동기로 활성화 명령을 내린다.
        - if : 다음 보스의 초기화가 다 완료되지 않았다면 
        → 해당 수정 체크포인트에서 해당 초기화가 완료될 때까지 대기한다. + 게임이 멈추지 않았음을 알리기 위해 “우 하단”에 Loading Cycle이 돌아가는 연출을 보인다. 
        → Boss의 모든 초기화가 완료되어 전투 준비가 완료되었다면 대기를 풀고 정상적으로 진행시킨다.

### 4. Boss EncounterTrigger와 상호작용

- Boss는 ‘**Save기록상 죽은 상태**’가 아니라면, **생성** 과정에서, Map의 정해진 위치에 Trigger 역할의 Collision을 생성하고 연결함 (다만 고민인 것이, 여기서는 Collision을 썼는데, 실제 전투에서는 코드 베이스의 Hitbox를 정의하고 사용한다. Collider를 전투 상태에서만 종료시킨다는 등으로 이를 어떻게 자연스럽게 만들지 고민할 필요가 있다.)
    - → 해당 Collision에 Player가 들어왔을 때,
        - if : 첫 조우일 경우 → player와 boss 모두 컷씬 상태가 됨 + 입장 조우 전용 컷씬을 재생함 → 컷씬 재생이 끝나면 들어온 문이 닫힘 + player와 boss가 서로의 **OnDie이벤트**를 구독함 + player와 boss 모두 전투 상태가 됨 → **SaveManager**를 통해 첫 조우 상태가 더이상 아님을 기록한다.
        - if : 첫 조우가 아닐 경우 → 재생이 끝나면 들어온 문이 닫힘 + player와 boss가 서로의 OnDie이벤트를 구독함 + player와 boss 모두 전투 상태가 됨

### 5. Boss의 생성

- 게임 첫 시작시 Map에 배치되는 경우
    - if : **SaveManager**로부터 확인했을 때 자신이 **사망**한 상태였다면 → 별도의 초기화 과정 없이, 바로 **사망 전용 Sprite만 생성하고 배치**하여 Ram 누수를 막는다. (이 판단을 복제된 boss prefab이 하게 할지, 아니면 외부에서 prefab을 복제하는 과정에서 알게 할지 고민)
    - if : **SaveManager**로부터 확인했을 때 자신이 **생존**한 상태였다면→ 지정된 위치에, 최초 초기화 과정을 진행함
- 플레이어가 사망했을 경우, **Player의 OnDie** 이벤트를 받음
    - → 체력을 **maxHP**로 초기화하고, 그 외 각종 수치들도 모두 기본값으로 초기화한 뒤, **player의 OnDie 이벤트** 구독을 끊고, 지정된 Boss의 base 위치로 이동한다.
    - → 초기화 과정에서 **EncounterTrigger**를 초기화 하여 지정된 위치에 지정된 크기만큼 생성한다.

### 6. Boss 사망

- Player의 공격으로 Boss가 사망시
    - → Player에게 **OnDie 이벤트**로 알림 + player와 boss가 **컷씬 상태**로 들어감
    - → 카메라가 Boss 쪽으로 이동함 + UI가 컷씬상태에서 정의된 움직임으로 감춰짐 + SaveManager에게 진행도 수정을 알림
    → Boss 사망 컷씬 시작
    - → boss 사망 컷씬 종료시, player와 boss의 서로의 OnDie 이벤트 구독 제거 + 컷씬 상태 종료 후 일반 상태 + 카메라 다시 player 쪽으로 이동함 + UI 복귀 됨
    - → 쓰러진 boss의 모든 연결을 끊어 Ram 누수가 없도록 함

### 7. Player 상태와 PlayerInput

- 플레이어가 ‘컷씬 상태’이면 → Input을 막는다. + UI 정의된 대로 감추는 연출을 한다 + 전용 연출 → 컷씬 상태가 끝나면 다시 복귀한다.
    - tutorial 과정과 연출로 발생하는 컷씬 (단, 아예 처음에 게임 시작을 해서 발생하는 tutorial 컷씬 연출 때에는 감추는 것이 없다.)
    - boss와 첫 조우시 및 사망시 발생하는 컷씬
    - ‘Slash’ 발동으로 인한 컷씬 연출
    - 컷씬의 연출은 누가 원인이든 간에 Game 전반에 영향을 주는 것이므로, 누구든 외부에 이러한 상태가 되었음을 알리고, 그것이 전체에 전달이 될 수 있도록 해야 한다.
- 플레이어가 ‘사망 상태’이면 → 컷씬 상태로 전환 + 사망 전용 연출
- 플레이어가 ‘부활 중’이면 → 컷씬 상태로 전환 + 체력 초기화
- 플레이어가 ‘회피 중’이면 → Input을 막는다
    - player 회피 버튼을 누를 시, 일정 시간동안 입력 불가 상태 (입력 불가 상태와 무적 지속 시간이 상이할 수 있다.)
- 플레이어가 ‘일반 공격’ 중이면 → Move 입력을 제외한 나머지 입력을 막는다.
    - Move 입력 역시, 평소 이동 속도보다 더 느린 이동속도로 이동하게 된다.
- 플레이어가 ‘Draw’이면 → Draw 전용 Input으로 전환한다.
- 플레이어가 ‘전투 중’이면 → ESC를 통한 설정창 띄우기 불가하도록 입력을 막는다.
    - player가 boss trigger를 밟는 순간 활성화된다.
    - player가 사망하거나 boss를 쓰러뜨리면 비활성화 된다.

### 8. Camera Move

- 카메라 모드가 Obeserver 모드임
    - → 매 Update마다 Player의 위치를 추적하되, 현 프레임에서 추적한 좌표를 1초에 걸쳐 천천히 따라붙도록 카메라 무빙을 설정한다.
- 특정 대상을 target으로 설정할 경우
    - → target 정보와 더불어 따라붙는 시간 (기본값 1초)을 전달
    - → 해당 Target을 향해 camera 중심을 옮김

### 9. 피격 판정 대상들

- Player 몸체
    - 피격을 Player에게 줄 수 있는 적 대상 : 적의 투사체, 적의 공격 (장판, 몸 피격 판정 활성화 등)
- 일반 공격
    - Player가 피격을 줄 수 있는 대상 : 적 몸체, 적 일반 구조물
- 특수 공격
    - Player가 피격을 줄 수 있는 대상 : 적 몸체, 적 일반 구조물, 적 특수 구조물 (특수 공격만 받음), 적 투사체 (제거 혹은 트리거 용도)

# 비고

## 1. Scene 전환 관련

1차 시안은, 하나의 Scene에 거대한 Map asset과 각각의 스테이지에 적들을 미리 배치해두되, 진행상황에 맞춰 활성화와 비활성화를 스위칭하는 것이다.

2차 시안은, 하나의 Scene에서 각각의 적에 맞게 적절한 Theme asset과 적을 배치하는 것. 플레이어가 방을 클리어하고 다음으로 나아갈 때, 로딩화면에 들어간다. 로딩 중에 하나의 Scene에 배치된 것들을 교체 및 이동시키고 다시 원래처럼 시작한다.

3차 시안은, 각 스테이지별로 별개의 Scene을 두어서, 방을 클리어하고 다음으로 나아갈 때 다음 Scene으로 교체하는 것이다.

이것과 관련하여, 우선은 1차 방법으로 제작하되, 각각의 방법을 비교하여 가장 성능이 좋은 것으로 선택한다.

## 2. 생성 및 로드시 코루틴 사용

Object를 생성하거나, Map에 배치하거나, 특정 상황을 구현해야 할 때, CutScene에서 순차적으로 animation을 재생해야 할 때 코루틴을 써보는 것을 고려중이다.

코루틴을 써서 병렬 처리했을 때의 로딩 속도와, 혹은 그 외의 방법을 써서 병렬처리를 했을 때 로딩 속도를 비교하여, 더 나은 것을 선택한다.

후보군은 다음과 같다.

- 1차 시안 Scene 전환을 쓸 때, 게임 실행시 1회에 한해서 Map 생성과, Boss들의 prefab 복사 및 생성 및 배치, Player의 prefab 복사 및 생성 및 배치를 해야 한다.
Map과 Boss의 생성과정을 `###Generator`라는 객체에서 코루틴으로 담당하게 한뒤 병렬화 하면 어떨까 싶다.
혹은, 그 이전의 체크포인트에서 비동기로 불러오게 하는 것도 좋은 것 같다.
- Player가 사망하고 마지막 체크포인트 지점으로 이동할 때, 플레이어 상태 초기화 및 이동과 보스 상태 초기화 및 배치가 이뤄져야 한다.
이때의 과정을 각각 코루틴으로 처리하면 어떨까 싶다.
- CutScene 재생시 해당 animation 출력과 카메라 무브, 배경 색 전환 등을 코루틴으로 다룬다.
