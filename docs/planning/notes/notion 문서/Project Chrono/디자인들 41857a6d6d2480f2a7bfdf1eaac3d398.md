# 2. In Game

## 로딩창

Title 화면에서 Save Slot을 눌러, 게임을 시작할 때, Map과 boss, player를 생성하고 배치하는 과정에서 띄워지게 되는 장면이다.

기본적으로 검은 화면에, 우측 하단에 로딩 중을 알리는 **로딩 도트 애니메이션**이 나온다. 아주 간단하게 링이 돌아가는 것을 표현하고자 한다.

로딩이 마쳐지면 아래 도트 애니메이션이 사라지고, 검은 화면에서 player camera 화면으로 자연스럽게 전환된다.

만약 인 게임내에서, 최적화를 위해 나중에 쓸 것을 비동기로 처리를 맡긴 것이 별도의 사유로 완료가 되지 않은 경우, 게임 화면을 정지 시키고, 시간이 기준 값을 넘기면 위에서 사용한 ‘도트 애니메이션’을 재활용하여, 플레이어에게 아직 게임이 정상 작동 중임을 알린다.

## 기본 UI 구성

기본적으로 UI에서는 4가지 정보를, 전투 중일 때에는 5가지 정보를 알려준다.

띄워질 수 있는 정보는 다음과 같다.

1. Player 체력 바 (좌 하단)
2. Player Draw 스킬 정보 (우 하단 1)
3. Player Slash 스킬 정보 (우 하단 2)
4. Groggy 에너지 게이지 (좌 중간)

## UI 연출

화면 밖으로 나가는 UI들은 공통적으로, 회색처럼 어두워지며, 속도는 60프레임 기준 10프레임 만에 외부로 나갈 정도이다.

반대로 화면안으로 다시 돌아오는 UI들은 공통적으로 색이 동일하며, 속도는 나가는 속도와 동일하다 (즉 역재생과도 같다)

### 컷 씬 “시작” 연출

컷씬이 시작되면 Player의 체력바와 스킬 정보, 그로기 게이지가 화면 밖으로 자연스럽게 나간다. 이때 나가는 속도는 10프레임 정도에 모두 나갈 수 있을 정도이다.

그후 지정된 컷씬이 발생한다.

이러한 연출을 쓰는 것은, 대표적으로 **보스를 첫 조우**할 때거나, **플레이어가 사망**했거나, **특정 구역에 입장**하여 컷씬으로 이어질 때이다.

### 보스 체력바 UI 연출

Player와 연관된 4개의 UI와 별개로 다루어진다.

보스전이 시작될 때 화면 밖 (상단)에서 아래로 내려와 화면 안의 특정 위치에 자리 잡게 된다.

보스의 체력이 모두 감소되었다면, 그 즉시 체력바가 그대로 사라지며, 이와 동시에 카메라의 중심이 적을 향해 잡히고 적의 사망 컷씬이 진행된다.

## 플레이어 사망 → 부활

Player의 UI와 (있다면 보스 UI)가 화면 밖으로 나간다. 

Player 화면에서 상단과 하단에 검은색 프레임이 안으로 일정량 들어와, player가 죽은 모습이 강조되도록 한다.

Player의 사망 animation이 모두 끝나면 아예 검은색으로 화면 전체를 가린다.

이후, 검은색 화면에서 Player Camera 시점으로 천천히 바뀌며, 그 시점에서 Player가 체크포인트 앞에서 일어나는 연출을 보인다. (이는 게임을 시작할 때 체크포인트에서 시작할 때 발생하는 연출과 동일하다)

## 보스 사망시

보스 UI가 사라지지만, 플레이어 UI는 유지된다.

보스의 사망 animation이 끝나면 플레이어로 포커스가 맞춰진다.

## Draw 스킬

UI들이 화면 밖으로 나가며, 화면이 살짝 어두워진다.

Draw 상태가 해제되면 다시 UI가 되돌아 온다.

Draw 상태에서는 살짝 어두워진 배경에 맞게 그려지는 Line이 보이도록 pixel FX가 필요하다.

## Slash 스킬

UI들이 화면 밖으로 나가며, 화면이 어두워진다.

이후 Player를 향해 줌이 땡겨졌다가 → 플레이어가 발도술을 하여 검을 검집 밖에 살짝 뺏다가 다시 안으로 집어넣는 순간 화면 이펙트와 함께 다시 카메라 줌이 원상태로 돌아오고 UI도 다시 화면안으로 돌아오며, 화면의 색이 돌아옴 → 이후 Line이 그려진 위치에 검격이 나간 듯한 이펙트가 한번 연출된 뒤→ 모든게 원래대로 돌아와서 계속 전투가 이어짐

여기서 쓰이기 위한 VFX로는, 검격이 나가는 위치에 그려지는 직선이 필요하다. 해당 직선은 katana zero의 공격 적중시 발생되는 직선 

또한 Slash스킬을 쓰기전 map에 시인성 있게 보여지는 line도 필요하다.

## 일반 공격

일반 공격의 animation을 8방향에 대해서 모두 구하기엔 쉽지 않다.

따라서, 무기 sprite를 특정 점을 중심으로 회전시키고, 실제 공격 판정이 일어나는 구역에 대해서는 검기가 나가는 FX를 통해 구현한다. 정확히는 특정 프레임 때 특정 각도 위치에 위치시키게 하고, 그 사이의 이동을 FX로 속이는 것이다.

검기는 하나의 검기를 왼→ 오(콤보 1) 일때와 오→ 왼(콤보 2) 일때 따로 만드는 것이 아닌, sprite를 뒤집어서 표현한다.

마지막 왼 → 오 → 왼(콤보 3)에서는 X자의 검기 FX를 따로 만든다. 한손검 검기의 모양이 프레임마다 어떻게 바뀌는지는 [텍스처 폴더](../../../../reference/sephiria/assets/Assets/Texture2D/)의 `Sword0_Swing` 프레임에서 확인한다.

공격시에는 기본적으로 검집채로 때리며, 검집에 들어가 있는 상태의 무기는 좌우 대칭이다. (검집을 차고 있는 sprite를 만드는 수고 덜기) Slash 때에만 칼을 꺼내도록 한다.

## Dash (회피)

Dash시, Dash 시점의 플레이어 Sprite를 대쉬 끝 위치로 옮기고, 그 사이의 것을 대쉬 시작지점에서 대쉬 끝 지점으로 올수록 간격이 더 촘촘해지는 동일한 sprite의 흐릿한 잔상을 남기는 것으로 표현한다.

# 3. Map

디자인 개발에 쓸 시간이 적으므로, 최소한의 소스들을 최대한 재활용 하여 구현한다.

특정한 경우가 아닌 이상, 흔히 영화에서 보이는 연구소의 하얀 실험방이 계속해서 쓰이게 될 것이며, 차이점은 그 실험방에 세겨지는 크랙이라던가, 혹은 아래의 사출 구멍이라던가 하는 정도의 차이밖에 없을 듯하다.

반복적으로 사용되는 전투 장소에 대해서 그 하나의 무대 전체를 Pixel png로 하나 만든 뒤, 필요하면 그곳에 여러 sprite들을 위에 쌓아 올려서 연출하는 것으로 쓰면 될 듯하다.

결국 만들어야 하는 pixel map은 복도 역할의 통로와, 전투의 무대가 될 실험방, 다음으로 나아가는 길을 막는 문, 그리고 체크포인트 역할을 할 수정이다.

이것의 완성은 player 캐릭터 이미지 확정 → 예시 보스 크기 확정 → 무대 크기확정 → 복도 & 문 크기 확정 → 수정 크기 확정

으로 이어진다.
