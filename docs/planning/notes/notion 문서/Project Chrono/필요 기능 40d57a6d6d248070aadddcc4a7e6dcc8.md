## 플레이어

플레이어의 조작으로 발생할 수 있는 모든 것들

- Case 0 : 일반 이동과 방향
    1. 플레이어의 **마우스 커서 위치를 실시간으로 추적**하여서, 그 위치에 맞춰 무기가 특정 점을 중심으로 회전한다.
    2. 플레이어의 **마우스 커서 위치를 실시간으로 추적**하여서, 플레이어가 바라보는 방향을 가운데 중앙 점을 지나는 세로 수직선과 가로 수직선을 기준으로 4방향의 자세 중 맞는 것을 표현한다.
    3. 플레이어의 마우스 커서 위치를 실시간으로 추적하여서, 플레이어가 현재 바라보는 방향과 반대 방향으로 이동하면 앞방향으로 이동하는 애니메이션을 역으로 재생하여 뒷걸음 치는 모션으로 출력함으로써 자연스럽게 표현한다.
    4. 플레이어의 w,a,s,d 키에 대해서, 각각 이동속도에 비례한 백터 값을 대응시켜, 키보드 기준 8방향으로 움직일 수 있게 한다. 키 다운이 되면 계속 해당 방향의 벡터값을 유지한다.
    이로 인해 여러 방향키가 눌릴 경우, 벡터가 합해져 특정 방향의 움직임이 상쇄되며, 이는 운동 백터값이 0이 되어 가만히 위치하게 되는 경우가 발생하게 될 것이다. (이는 의도된 사항)
    5. 더 정확하게는, 플레이어 스프라이트에 대해, 마우스 커서는 ‘플레이어 캐릭터가 바라보는 방향 벡터’를 결정하고, 키보드 wasd 입력은 ‘플레이어 캐릭터의 운동 벡터’를 결정한다.
- Case 1 : 공격
    1. 플레이어가 마우스의 커서를 특정 위치에 가져다 놓은 뒤, 마우스 클릭을 하여, 커서 위치의 특정 영역에 공격을 가함.
    2. 공격을 가한 뒤에 일정한 간격을 두고 대기 시간이 존재한다. 이 시간 동안에는 공격 신호가 들어와도 공격을 가하지 않는다.
    3. 플레이어가 취한 일반 공격 모션이 특정 프레임에 다다르는 순간 검이 휘둘러진 특정 영역에 N프레임 동안 ‘공격 판정’이 일어나야 함.
    4. 공격 동작 중 N프레임 동안은 공격 모션을 취하고 있어 이 행동 동안에는 ‘wasd를 통한 느린 움직임’을 제외하고 Draw & Slash, 대시 등의 다른 행동이 불가하다.
    5. 일정 시간 내에 일반 공격을 연속해서 총 3회로 이루어진 콤보 공격이 가능하다.
    6. 마우스 클릭을 쭉 누르는 경우 일반 공격 모션이 끝난 뒤에 곧바로 공격 명령이 들어간것으로 취급되어 다음 일반 공격 모션을 취하게 된다.
    7. “공격 속도 수치”는 공격시 실행되는 animation 속도를 배속 시키며, 공격과 공격 사이의 대기 시간도 일정 비율로 감소시킨다.
- Case 2 : 대시
    1. 플레이어가 대시할 경우, 플레이어는 마우스 커서 방향을 바라본 자세를 기반으로, 이동 경로에 그 자세의 잔상을 남긴다.
    2. 플레이어가 이동 명령을 내리지 않은 상태에서, 마우스 커서를 특정 위치에 두고 대시 키를 누르면 그 위치로 대시를 하게 된다.
    3. 플레이어가 이동 명령을 내려 특정 방향으로 운동하고 있는 상태에서, 대시키를 누르면 마우스 커서위치에 상관없이 그 운동방향으로 대시를 하게 된다.
    4. 대시를 할 때, 대시 시작부터 N프레임 동안 ‘피격 무시’ 상태이며, 시작부터 M 프레임 동안은 다른 입력이 무시된다. M 프레임 이후에는 키 다운 입력 뿐만아니라, 그 이전부터 키 다운으로 입력되던 것들도 반영된다. (가령, a 를 누르며 왼쪽으로 이동하다가 대시를 눌렀을 때, 계속 a를 누르고 있었다면 대시가 끝난 뒤에도 입력 가능 타이밍 부터 왼쪽으로 이동하는 애니메이션이 출력됨.)
    5. 대시를 한 이후 일정 시간 간격동안 다시 대시를 할 수 없다.
- Case 3 : 스킬
    1. 플레이어의 ‘스킬’은, 기본적으로 쿨타임이 모두 돌아 사용 가능할 때에만 스킬을 사용할 수 있다.
    2. 플레이어의 ‘Draw’ 스킬을 사용하면, ‘정신 집중 상태’에 들어간다.
    3. 플레이어가 ‘정신 집중 상태’에 들어가면, 플레이어를 제외한 나머지 요소들의 시간이 모두 정지하며 밝기가 낮아진다.
    4. ‘정신 집중’ 상태에서 특정 행동을 하는 것 외에는 다른 행동을 유발하는 입력은 모두 무시된다.
    5. ‘정신 집중’ 상태에서는 마우스 클릭이 ‘점’을 찍는 요소가 된다. 
    첫 번째 점은 시작점으로써, 존재하게 되는 순간, 해당 지점을 시작점으로 사용하는 화살표가 생성된다. 해당 화살표는 길이가 정해진 값을 그대로 유지하며 마우스 커서를 따라 방향을 이동한다.
    두 번째 점은 끝점으로써, 화살표의 방향이 결정되고, ‘경로 확정’이 가능해진다.
    6. ‘경로 확정’시, 화살표가 ‘경로’가 되며 ‘정신 집중’ 상태가 해제된다. ‘Draw’ 스킬에 짧은 재사용 대기시간이 주어지고,  비활성화 되어 있던 ‘Slash’ 스킬이 활성화됨과 동시에 짧은 쿨타임이 부과된다.
    7. ‘경로’가 존재할 때, ‘Draw’ 스킬을 사용하면 이전에 존재하던 ‘경로’는 제거되고 다시 처음부터 ‘점’을 찍어야 한다.
    8. 플레이어는 ‘경로’가 존재할 때에만 ‘Slash’ 스킬을 사용가능하며, ‘경로’는 생성된지 일정 시간이 지나거나 ‘Slash’ 스킬을 사용하면 제거된다. 
    9. ‘Slash’ 스킬을 사용하면 ‘발도’ 상태에 들어간다.
    10. ‘발도’ 상태에서는 시간이 정지에 가깝게 느려지며, ‘경로’에 발도술이 나가 해당 위치에 존재하는 적 개체들에게 피해를 주며, 투사체를 제거한다.
    11. ‘발도’ 상태 동안, 플레이어를 중심으로 카메라가 살짝 확대되었다가, 특정 sprite animation이 출력된 뒤에 다시 원상태로 돌아간다. 
    12. ‘발도’가 사용된 뒤, ‘Draw’는 일정량의 쿨타임이 주어지며, ‘Slash’는 ‘경로’가 없어졌다는 이유로 비활성화된다.
- Case 4 : 피격
    1. 플레이어에게 종속된 Hitbox는 외부에서 충돌 검사를 할 수 있으며, 플레이어에게는 외부에서 호출 가능한 ‘TakeDamage()’가 존재한다.
    2. ‘TakeDamage()’를 통해, 실제로 플레이어의 체력이 감소되었다면 ‘피격’ 상태에 들어간다.
    3. ‘피격’상태 동안, 플레이어의 캐릭터는 투명색으로 깜빡거리며, ‘피격 무시’ 상태가 된다.
    4. ‘피격 무시’상태가 되면, Hitbox 겹침으로 인해 호출되는 TakeDamage의 피해를 무시한다.
    5. ‘피격’ 상태의 길이는 곧 ‘피격’으로 인한 ‘피격 무시’ 상태의 유지시간과 같으며, 이 시간동안 플레이어 캐릭터의 깜빡거림이 유지된다.
- Case 5 : 사망
    1. 플레이어의 체력이 0이하로 내려가면, 모든 실행중이던 것이 멈추고 ‘사망’ 상태에 들어간다.
    2. ‘사망’ 상태가 되면, 플레이어를 제외한 게임 내 시간이 멈추고 흑백이 되며 어두워진다. 
    3. ‘사망’ 상태가 되면, 플레이어의 모든 상태나 버프와 행동이 중단되며, 사망 전용 연출 (animation과 VFX)이 출력된다.
    4. 사망 연출이 끝나면 ‘마지막 체크포인트’로 이동한다.
- Case 6 : 생성
    1. 기본적으로 플레이어는 ‘체크포인트’ 위치에서 ‘생성’된다. 체크포인트 종류는, 플레이어가 상호작용하여 갱신되는 수정으로 된 체크포인트 장소와, 보스를 죽인 직후 자동으로 갱신되는 체크포인트로 나뉜다.
    2. 플레이어의 생성은 두 종류로, “게임을 시작했을 때 마지막 체크포인트에서 시작(이하 ‘첫시작’)”되는 것과, “게임 중 사망하여 마지막 체크포인트에서 부활(이하 ‘부활’)”하는 것이다.
    3. ‘첫 시작’시에는 플레이어가 사용하는 기능과 이벤트들에 연결되고 자신을 전달한다. 그 다음에는 자신을 마지막 체크포인트 위치로 옮기고, 수치 값들을 기본값으로 초기화한다.
    만약 마지막 저장위치가 체크포인트 장소가 아니라, 보스를 죽인 직후라면 그 때의 HP 상태를 복원한다.
    4. ‘부활’될 때에는, 플레이어의 위치를 마지막 체크포인트 위치로 옮기고, 수치 값들을 기본 값으로 초기화하고 HP는 maxHP로 초기화한다. 

시스템

- Case 1 : ~~모드~~
    - 굳이 “모드”라는 이름 하에 FSM을 사용해야 하나? 일반과 전투는 Player의 State로 처리해버리고, 컷씬과 사망은
    - 모드는 단 하나만 활성화되며, 다른 모드가 활성화되면 기존의 모드는 종료된다.
    - ‘일반’모드
        - 플레이어는 모든 조작이 가능하다. 보스도 존재하지만 ‘전투’ 모드가 아닌 보스는 데미지를 입지 않는다.
        - 일반 모드에서만 esc키를 눌러 ‘세팅창’열기가 가능해진다.
        - 일반 모드에서, 체크포인트를 활성화 하면 플레이어의 체력이 모두 회복되며 그로기 게이지가 초기화되고 체크포인트 장소가 갱신된다. 체크포인트가 활성화되어야 루트가 열린다.
    - ‘전투’모드
        - 플레이어가 특정 보스방의 특정 Trigger를 밟는 순간 활성화된다.
        - 보스가 ‘전투’ 모드의 활성화에 따라 플레이어를 공격 대상으로 인식하고 플레이어의 공격에 데미지를 입기 시작한다.(이부분을 Bool이 아닌 더 효율적인 방법으로 추후에 고민) 또한 보스적의 체력 UI가 활성화된다.
        - ‘전투’모드에서 활성화된 보스가 사망시, 보스에 개별적으로 설정된 ‘컷씬’으로 넘어간다. 컷씬이 끝나면 ‘일반’모드로 들어간다.
        - ‘전투’모드에서 플레이어가 사망시, 플레이어 개별의 사망 애니메이션 출력과 함께 게임 내 시간을 정지 시킨다. 이후 사망 전용 UI 연출이 출력된 뒤, 체크포인트로 자동이동한다. (다크소울처럼)
    - ‘컷씬’모드
        - 플레이어의 키 입력 조작이 불가하다. 준비된 연출과 animatin과 VFX가 타이밍에 맞춰 출력된다.
        - 컷씬 연출이 모두 마무리되면, 해당 컷씬에 설정한 모드로 돌아간다.
    - ‘사망’모드
        - 플레이어의 체력이 0이하로 떨어지면, 사망 모드로 전환된다.
        - 사망 모드의 전환이 감지되면, 플레이어의 사망 연출과, 게임 내 시간 정지, 사망 전용 UI 등을 담당한다. 이후 체크포인트로의 자동이동까지 이뤄진 뒤, ‘일반’ 모드로 전환하도록 한다.
- Case 2 : 진행상황
    - 플레이어의 진행상황은 다음의 경우에 갱신된다.
        - 새로운 체크포인트를 활성화 → 생성 혹은 게임 시작시 해당 위치에서 시작
        - 적 보스를 쓰러뜨림 → 게임 재시작시, 해당 보스가 쓰러진 상황에서 마지막 체크포인트 장소에서 시작
        - 적 보스를 처음으로 조우 → 첫 조우시에만 컷씬을 보이며, 이후 재시작에서는 컷씬을 보이지 않도록 체크한다.
    - 진행상황을 “체크포인트”와 “적 보스 클리어”로 나누어 저장하며, 퍼센티지 값 갱신은 ‘체크포인트’ 기준으로 갱신된다.
    - 마지막 보스를 쓰러뜨리면, 자동으로 바로 엔딩으로 직결되는 컷씬이 발동한다. 여기서 체크포인트는 ‘엔딩’ 컷씬이 시작되는 부분이다.
    - 튜토리얼의 경우, “이동 안내 → 체크포인트 안내(이때 체크포인트 갱신) → 튜토 보스 입장 → 특수 공격기 안내를 위한 정지 장면 → 기본 공격 안내 → 회피 안내 → 튜토 보스 클리어”로 이어진다. (Furi 첫 보스전 참고)
- Case 3 : 카메라 무브
    - 기본적으로 플레이어를 중심에 둔다. 플레이어 캐릭터가 특정 방향으로 이동하면 카메라는 약간의 시간차를 두고 부드럽게 따라간다.
    - “컷씬”에서는 카메라의 중심점이 계속 달라질 수 있으며, 이에 대해서 카메라가 갑자기 급작스럽게 변하는게 아닌 카메라 1대가 그 사이를 특정한 속도로 이동하도록 하여 전환한다.
    - 플레이어가 Draw를 할 때에는, 플레이어의 중심으로부터 마우스 커서가 이동한 방향과 그 거리에 따라서 카메라의 중심을 옮긴다. 이를 통해 플레이어가 제한된 화면에서도 Draw 가능 범위가 넓어질 수 있도록 한다. (Enter the gungeon의 커서에 따른 카메라 움직임 참고)
    - 플레이어가 사망하면, 플레이어의 중심을 향해 카메라가 이동한다. 이 역시 갑작스럽게 순간 이동하는 것이 아닌, 어느정도의 이동 과정이 보이도록 한다. 이 과정과 함께 플레이어의 사망 animation이 출력된다.

보스

- Case 1 : 배치 및 조우
    1. 모든 보스는, Scene 내의 특정 위치에 비활성화 상태로 미리 배치되어 있다. (이 부분은 나중에 최적화 요소로 둘 예정) 미리 배치되어 있음에도 비활성화되어 있기 때문에 플레이어의 공격에 피격당하지 않는다.
    2. 플레이어가 맵의 특정 Trigger 위치에 도달하면, 시스템이 ‘전투’ 상태로 들어간다. 
    3. ‘전투’상태가 될 때, Trigger에 등록된 필드에 대기 상태로 존재하던 보스 객체에 신호가 감으로써 보스는 활성화된다.
    4. 활성화된 보스는 자신의 체력 UI를 띄우며, 플레이어를 위치를 추적하여 패턴을 실행한다.
- Case 2 : 전투 상태
    1. ‘전투’ 상태가 된 보스는 내부적으로 Idle 상태와 Pattern # 상태를 왔다갔다 반복한다.
    2. 모든 Pattern에는 해당 패턴으로 넘어가기 위한 ‘조건’이 존재한다. 해당 조건은 ‘해당 패턴이 마지막으로 사용된 순간으로부터 최소 시간을 만족하였는가’, ‘다른 패턴이 N개 활성화 되었었는가’, ‘특정 피 상황을 만족하는가’, ‘특정 위치에 도달해 있는가’ 등이 있다.
    3. ‘조건’이 만족된 패턴이 여러개라면, 그 중에서 공평한 확률로 1개를 택하며 (모듈러 편향 주의) , 패턴에는 가중치가 존재해 다른 패턴들보다 더 우선적으로 선택되게 할 수 있다.
    4. 패턴은, 특정 투사체를 특정 방향으로 여러개 발사하거나, 특정 위치로 이동하거나, 빠르게 움직이거나, 지형지물을 변화시키거나 하는 등 여러가지가 다양하게 구현될 가능성이 있다.
- Case 3 : 사망 상태
    1. 보스의 체력이 0이 되면, 전용 사망 컷씬이 재생된다. 그동안 플레이어는 무적 상태 (아니면 피격 무시?)가 되며, 조작이 불가하다. ( Enter the gungeon 레퍼런스 )
    2. 보스의 사망시 다음으로 향하는 문이 열린다. 또한 진행상황이 갱신되게 된다.

보스마다 (만약에 존재한다면) 1회 한정으로 재생되는 입장 컷씬과, 사망시 발생하는 사망 컷씬이 존재한다.

“시스템’적으로 조정해야 하는 수치들과, ‘게임 중 런타임에 변경되는 값’을 구분해야 한다.

## ||Mode-State-Condition

모든 상태와 모드는 Enum을 통해 열거하며, 이후 ‘이진수’로 나타내는 것으로 변경하여 성능 차이를 비교한다.

- 상태
    - 모드(Mode) : 서로 다른 모드들 끼리 양립할 수 없으며, ‘일반’ 모드와 ‘전투’ 모드에서는 아래의 상태를 가질 수 있다.
        - 튜토리얼 모드
            - 튜토리얼 때, 각 스킬에 대해서 입력을 대기하고 이를 알려주는 등의 안내 시스템과 연결된 상태
        - 컷씬 모드
            - 설정 혹은 넘기기를 제외한 조작이 불가하며, 컷씬이 끝난 뒤에 다시 ‘일반 상태’로 이동함
        - ‘초기화’ 모드
            - Status들이 초기화되고, 스킬 쿨타임이 초기화되며, 다른 상태들이 종료됨
        - 일반 모드
            - 적과 상호작용을 하지 않고 있는 상태이나, attack, draw & slash, dodge 등 전투에서의 조작들도 모두 가능
            - 체력 소모가 일어나지 않는 상태이므로 체력 UI가 뜨지 않거나, 풀피 상태이다.
        - 전투 모드
            - 적과 상호작용이 가능한 상태
            - 전투 상태에서는 추가로 ‘각성 상태’에 들어갈 수 있음 (그런데 애초에 각성 상태의 trigger가 되는 공격이 전투 상황에서만 나오므로 이러한 제약이 굳이 없어도 됨)
        - 사망 모드
            - 체력이 모두 떨어져 0 이하가 되면, 연출이후 자동으로 마지막 체크포인트로 이동한다.
    - 상태(State) : ‘일반’ 때와 ‘전투’ 모드 때, 같이 켜지는 상태들, 기본적으로 여러 상태가 동시에 켜질 수 없다.  특정 상태로 변경되면, 그에 따른 함수를 실행시켜서 외부로 알리거나 (animation, vfx) condition 값을 조정한다.
        - 일반 상태
            - 어떠한 상태로 정의되지 않는 경우 취해지는 기본 상태
            - 다음의 행동에 따라 타 상태로 전이된다.
                - Draw 시작 함수 호출시 → Draw 상태
                - Slash 시작 함수 호출시 → Slash 상태
                - Dodge 시작 함수 호출시 → 회피 상태
                - 피격시 → 피격 상태
                - 공격 시작 함수 호출시 → 공격 상태
        - 공격 상태
            - 플레이어가 공격을 취하게 되는 상태이다.
            - 공격 상태가 특정 지점까지 계속 유지되고 있어야 공격이 나가는 프레임 동안 실제 피격 판정이 발생한다.
            - 공격 상태 중 다른 상태로 전이되면 공격 횟수 카운터가 초기화 되며, 연속 동장의 초기 동작으로 돌아간다. (이동하거나, 회피하거나, draw, slash를 하거나 등등, 피격은 상관 x)
            - 공격 상태로 변경된 후, 일정 시간이 지나면 다시 일반 상태로 돌아가며 횟수 카운터와 자세도 초기화 된다.
            - 공격 상태가 진행될 때마다 공격 횟수 카운터가 1 증가하며, 카운터의 현재 값에 따라 출력되는 애니메이션이 달라진다.
        - 회피 상태
            - 플레이어가 회피 동작을 취하는 상태이다.
            - 이 상태의 특정 시간 동안까지 다른 상태로의 전이는 불가하며, 또 다른 특정 시간동안 ‘무적’ 상태가 유지된다.
            - 회피 animation 지속과, 실제 다른 입력 가능 시점의 시작 지점의 차이가 존재하게 할 것인지를 확인해 볼 필요가 있다.
        - 피격 상태
            - 플레이어가 적의 공격에 맞은 상태이다.
            - 이 상태에 돌입되는 순간, 피격 화면 연출과 함께 플레이어는 무적 상태를 얻으며, 무적을 알리는 깜빡임이 나타난다.
        - Draw 상태
            - 시간이 정지하고 플레이어를 제외한 나머지 요소들이 흑백 + 살짝 어두워지며, 마우스 커서와 안내 키 문구가 뜸
            - 마우스 클릭시 해당 지점을 중심으로 시작되는 직선을 생성하며, 마우스 커서 위치를 추적한다.
            - 시작 지점이 존재하는 상황에서, 다시 마우스 클릭을 할경우, 그 방향으로 나아가는 직선을 확정한다.
            - Draw 상태에서는 (일단은) 다른 상태로의 전이가 불가능하다.
        - Slash 상태
            - Draw가 존재하는 상황에서, Slash 키를 눌렀을 때 활성화된다.
            - 시간이 정지에 가깝게 느려지며, 플레이어를 중심으로 카메라가 확대되었다가 다시 원상태로 돌아간다.
    - 상태(Condition) : State와 다르게, 여러개의 Condition은 같이 양립될 수 있다. 지속 시간이 존재하여 이곳에서 다뤄진다. (아예 여기서는 상태의 진입과 이를 알리는 bool 값으로만 쓰이고, 지속시간을 코루틴과 특정 함수에서 종합적으로 다루는, 두 경우를 비교하면 좋을 것 같음.)
        - 각성 상태
            - 특정 조건을 만족하여, 일시적으로 강해진 상태임을 알리는 bool 값
            - 공격력, 공격 속도, 이동속도가 소폭 상승하고, 체력을 소폭 회복한다.
            - 각성 상태를 알리는 VFX가 플레이어를 중심으로 나타난다.
            - 각성 상태를 bool 값으로 하여 status 값을 조정하면, 해당 status 값을 호출할 때마다 필연적으로 ‘분기 예측’이 발생 할 수 밖에 없는데, 이걸 어떻게 해결하면 좋을지 고민해볼 필요 있음. (상태 변경시 마다 수치 값 대입하기 or 배열 사용하기 or 삼항 연산자 쓰기)
        - 무적 상태
            - 데미지 피격 호출이 무시되는 상태임을 알리는 bool 값
            - 무적 상태의 발생자가 누구냐에 따라 지속시간이 다르다., 그래서 animation event로 할지, 아니면 update로 조작할지 고민 중
        - 공격 횟수 카운터
            - 공격 상태가 유지된 상태에서 계속해서 공격 신호가 들어올 경우, 카운터가 증가한다.
            - 카운터에 따라, 공격 연속 동작 중 어느 것을 취할지가 결정된다.
        - Draw Line 시작 점 존재
            - Draw Line의 시작 점의 존재 여부 및 해당 좌표를 저장한다.
            - Draw Line의 시작점이 존재해야 끝 점이 null이 아닌 값이 저장될 수 있다.
        - Draw Line 끝 점 존재
            - Draw Line의 끝 점의 존재 여부 및 해당 좌표를 저장한다.
            - 끝 점이 존재해야 Slash가 가능하다. (안전하지는 않지만, 로직 대로라면 적어도 “끝점이 있어야 한다는 것”이기 때문에
        - 디버프
            - 아직은 고려하지 않았으나, 디버프가 적용된다면 여기서 다뤄지지 않을까 생각된다.
- 스테이터스
    - 수치
        - 체력 : 특정값으로 초기화된 체력을 보유하고 있음. 특정 조건을 만족할 경우, 체력이 일정량 회복됨. 모든 체력이 감소될 경우, '사망'상태가 됨.
        - 공격력 : 플레이어가 취하는 모든 공격 행동에 관여하는 수치. 세부 수치 조정을 위해 '10'이 기본 값이며, 공격력 = 데미지를 기준으로 한다.
        - 공격속도 : 플레이어가 입력을 통해 공격 동작 지시를 내렸을 때, 그것을 실제로 받아들여서 그것을 실제 공격으로 연계할지 여부를 결정하는 수치. 만약 '공격을 할 수 있는 상태'가 아니면 공격하지 못함
        - 이동속도 : 플레이어가 이동 입력을 넣었을 때, 프레임당 움직이는 거리를 결정함. 관성은 존재하지 않음.
        - 그로기 게이지 : 지운 투사체의 총 수에 비례하여 게이지가 참. 모든 게이지가 차면, 적을 그로기 상태로 만듦
        - 공격 콤보 카운터 (플레이어 스테이터스에 둘지는 [참고 코드](<../../../../reference/sephiria/code/ingame code/Assembly-CSharp/>)와 던그리드의 상태 관리 방식을 확인한 뒤 결정)
    - 특정 상태 판정을 위한 bool 값 (스테이터스에서 해당 값까지 처리하는게 맞을까?)
        - 각성 여부
        - dodge 여부 (키 입력 무시를 위한)
        - 피격 여부
        - 무적 여부
        - Draw 존재 여부
- 입력
    - 공격 (M1) : 기본 공격을 마우스 커서 위치 방향을 중심으로 하는 호를 그리며 시전한다. 총 3단계에 걸친 공격 모션이 존재한다. 중간에 이동 명령 없이 계속해서 공격 명령을 내리면 단순 공격을 했을 때보다 더 강한 공격이 이어서 나간다. 공격의 모션 중에는 칼에 피격 범위가 생겨 이것에 맞은 적은 피해를 1회 받는다 (동일 적이 하나의 공격에 다단 히트 불가)
    - 회피 (space) : 플레이어가 회피 명령을 내리면 특정 거리를 빠르게 대시하며, 이동하는 순간은 무적 상태임. 회피를 사용하면 다음 회피 가능 시간까지 회피를 하지 못함. 그 외에 회피를 제한하는 별도의 요소는 없음. 'Furi'의 회피와, 'Enter the Gungeon'의 회피가 레퍼런스로, 회피 횟수에 거는 자원 제약이 없어도 까다롭게금 할 필요가 있음 (대개, '회피'를 눌러도 그 이동한 자리에 탄막 혹은 장판이 깔려 있을 정도로 촘촘하거나 넓은 경우가 대다수임)
    - Draw(shift) & Slash(f) : Draw 상태와 Slash 상태로 나뉨. Draw 상태가 되면 마우스 좌클릭은 시작, 첫 좌클릭 이후 마우스 이동 위치를 실시간으로 계산해 어느 방향으로 직선을 그릴지 preview를 보여주며, 다시 좌클릭을 누르면 확정한다. 마우스 우클릭을 하면 그린 직선을 모두 지운다. Shift 키로 Draw 상태를 취소, F키로 Draw를 확정할 수 있다.
- 보스전 첫 입장시 흐름
    - 문이 막혀 있고 옆에는 체크포인트 보석이 존재함 → F를 눌러 상호작용 가능
    - 체크포인트에 체크하면 → 위치 갱신 및 체크포인트 활성화 기록 → 보석 활성화 animation → 보스문 열림 animation과 함께 해당 구역 이동 가능해짐
    - 보스전 전용 map에 일정 거리 이상으로 들어오면 → 보스 문 닫힘 animation → 보스 전 전용 입장 컷씬 → 보스전 진행
- 사망시 행동 흐름
    - 체력이 0 이하로 떨어짐 → 사망 트리거 발동
    - 사망 모드로 전환 → 전용 애니메이션 및 VFX 출력 후 → 재시작을 물어보는 UI 등장
    - 재시작 선택했다는 함수 발동시 → 마지막 체크포인트 기록으로 이동 → 체력 및 그외 스테이터스 기본 값으로 초기화 → 해당 체크포인트에서는 문이 이미 열려 잇으며, 보석은 활성화되어 있음 → 보스전 전용 map에 입장시 동일 trigger 위치에서 보스 문 닫힘 animation이 재생되고, 곧바로 보스전 진행 (즉, 보스전 전용 입장 컷씬 없이 진행)

# 적

- 플레이어와의 상호작용
    - 인스턴스로 생겨난 공격에 대해, 플레이어가 해당 공격을 한 번 맞으면 그 공격에 대해서는 다시 피해를 입지 않는다. (하나의 공격에 중복 피격 되는 현상 제어)
    - 몸체에 닿아도 되는 것과 닿지 않아야 하는 것의 구분
        - 움직이지 않는다 = 몸이 닿아도 됨
        - 움직인다 = 닿으면 피격 판정됨
        - 가장 좋은건, 가까이 붙어있으면 탄환 공격을 눈으로 보고 대응할 수 없기에 멀리 떨어져 있어야 하는 행동양식이 발생해야 함. 즉, 근접 공격을 해야하는 플레이어의 특성상, 일반 상황에서 몸이 닿았다고 피격 처리가 되는건 그렇긴 해.
- 상태
    
    첫 입장시 : 외부 -> 입장 -> 입장 컷씬 -> 초기화 -> 패턴 상태 돌입
    n번 째 입장시 : 초기화 -> 패턴 상태
    
    - 초기화 상태 : 모든 수치가 초기의 상태로 되돌아감
    - 입장 컷씬 상태? : 이는 시스템에 의해서 발동
    - 패턴 상태 : Idle - 패턴 n - Idle - 패턴 m ... 순서대로 흘러감, 각 적마다 다르게 패턴과, 각 패턴별 사용되는 조건 (특정 상황 or 특정 위치, 특정 시간 대기 등등)이 설정되어야 함. 패턴 상태에 처음 돌입하게 되면 반드시 idle 상태에서 시작되어야 함.
    - 그로기 상태 : 외부에 의해서 그로기 상태가 강제되면, 실행중이던 모든 행동이 멈추고 그로기 상태에 돌입해야 함.
    - 사망 상태 : 모든 체력이 감소하였을 때, 사망 상태에 빠짐
- 스테이터스
    - 공격력 : 모든 공격의 기본 베이스가 됨.
    - 체력 : 스테이지가 시작될 때마다 초기화가 됨
- 탄환/공격 종류
    - Slash로 지울 수 있는 공격 : 기본적으로 모든 '탄환'류는 지울 수 있다. 붉은 색이다.
    - Slash를 맞추었을 때 이득을 볼 수 있는 공격 : '황금색', 혹은 '푸른색 오라' (lost ark 카운터)
    - Slash를 맞추는 것과 상관 없는 공격
    - 탄환은 각각 피격 판정이 존재하며, 플레이어가 해당 공격에 맞을 경우 해당 탄환은 사라진다.

    - key세팅값에 맞춰서 입력이 들어가도록 함
